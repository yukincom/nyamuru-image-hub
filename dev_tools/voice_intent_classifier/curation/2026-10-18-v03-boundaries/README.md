# ニャムル音声分類 v0.3向け追加データ

否定・延期、Undo／Redo、複数操作の境界を各96件、**計288件**追加しました。すべて合成例で、**学習専用候補**です。[全例と注釈](review.md)を参照してください。

既存924件・19分類は変更していません。候補全体では1,212件となりますが、1,212件をすべて訓練する指示ではありません。Colab担当が訓練poolと評価poolを明示して構成します。元316件の4ファイルも保持しています。

- `candidates.jsonl`: 追加288件。入力は `text` のみ、教師は `label`。`slots`・注記・ID・family等をモデルへ入力しない。
- `labels.json`: 既存19分類の定義をバイト単位で保持したコピー。新しい実行経路は追加しない。
- `family-links.json`: 各groupと、関連するv0.2のID・group・family・元split。言い換えの系譜を保持する。
- `regression-evidence.json`: 既存testの誤分類原文・スコア・確率を保持した診断資料。新しい学習例や独立テストと混ぜない。
- `manifest.json` / `validation.json`: 由来、件数、ハッシュ、検証結果。`validate.py`で検査を再実行できる。

## Colab担当への引継条件

1. 追加288件は全件train-only。既存dev/testの結果を見た後の補強であり、近い例をランダム分割で新testへ移さない。元924件と旧splitは上書きしない。
2. v0.2 dev/testは凍結した**旧版の回帰診断**として保持する。追加例には旧dev/testのfamilyに近い例があるため、追加後の旧test成績を新たな独立精度として報告しない。既存のfamily非重複検査を黙って無効化せず、訓練pool／旧診断pool／新dev／新testのmanifestを分ける。
3. 95%の達成判定には、訓練poolから独立した新しいdev/testを準備し、19分類のラベルレビュー、近似例・対照例のfamily照合、ハッシュ固定を**学習前**に行う。実利用者の未使用発話を優先し、合成文の場合はその限定を明示する。今回の追加288件を切り出したtestでは代用しない。
4. 目標は新testの19分類全体の正解率95%以上。分類別件数・正解率、macro-F1、非命令→操作、Undo↔Redo、複数操作→単一操作も併記する。全体95%だけで実操作への採用を決めない。
5. モデル条件と採用seedの選択規則は新devだけで確定し、testを見る前に保存する。test最高seedの後付け選択はしない。新しい独立testが用意できなければ「旧testでの改善確認まで、95%達成判定は未実施」とする。
6. 現モデル／ラベルIDを維持して比較し、追加データだけで特定分類に偏らないよう、基礎19分類の性能低下も確認する。学習ノートブックと入力ZIPを次回Colab実行用に準備する。ここでは学習・モデル推論・ASR・アプリ接続は実行していない。

新testの誤りを見て次の補強へ使う場合、そのtestも以後は回帰診断として扱います。slotsは人手の正解注釈であり、この分類器が引数を抽出できることの証拠ではありません。

## 保存後の検証

元の結果ZIPを手元に用意し、`python3 validate.py --baseline-zip /path/to/nyamuru-voice-v02-colab-results.zip` で検証します。省略時は現在の利用者の `~/Downloads/` を参照します。元ZIPはこのGitに含みません。`validation.json` は2026-10-18時点の記録であり、その後の保存先表記変更の検証結果ではありません。原記録は [ModernBERTの保存資料](../../../../docs/ModernBERT/README.md)にもあります。
