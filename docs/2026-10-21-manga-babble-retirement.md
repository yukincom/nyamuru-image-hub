# 旧Bubble Makerへのモデル依存の解消（2026-10-21）

以前に「漫画バブルメイカーから参照するのをやめ、ニャムル内で完結させる」と利用者から指定されていたが、RT-DETRのモデルへのシンボリックリンクが残っていた。旧プロジェクトの公開保存・ローカル撤去に先立つ今回の点検で判明した。

## 残っていた依存

ニャムルの`.local-vision/models/rtdetrv4-x-manga109s_v2/model.onnx`は、通常ファイルではなく、隣の`manga-babble-maker/models/rtdetrv4-x-manga109s_v2/model.onnx`を指す絶対パスのリンクだった。表示上はニャムル内のパスでも、実体は旧プロジェクトに依存しており、そのフォルダを削除するとコマ・文字領域などの検出が使えなくなる状態だった。

コードの移植と保存パスの存在確認だけでは、実行環境の独立を確認したことにならない。以前の指示を満たしていなかった点として記録する。

## 今回の修正

同じ重みをニャムルの既存保存先へコピーし、SHA-256を確認してからリンクと原子的に置き換えた。新しい参照経路やモデルのダウンロードは追加していない。推論コード・設定・閾値も変更していない。

- 現在の実体：`.local-vision/models/rtdetrv4-x-manga109s_v2/model.onnx`（通常ファイル）
- サイズ：250,159,393 bytes
- SHA-256：`5a5c27646a2ae2e9c85671a1db30504debc9b0b816dc585235435c5e86c2c2b9`

旧モデルと配置後のモデルを、現在のニャムルのRT-DETR推論コードと同じ自作ネーム画像で比較し、検出結果が一致した（body 2件、frame 6件、text・face 0件）。白紙画像での起動確認も実施した。これはモデル配置と同一入力での出力一致の確認であり、新しい検出精度の評価ではない。

`scripts/`・`src/`と解析用Python環境のパス定義に、旧`manga-babble-maker`のコードを実行・importする参照は見つからなかった。今後も、旧プロジェクトへのリンクを作って配置不足を埋めず、モデル実体・symlink・起動先を確認する。

漫画バブルメイカーは、ニャムル側の制作パイプラインへ一本化するため開発終了。コードと過去の開発記録・素材・試験出力は[元のGitHubリポジトリ](https://github.com/yukincom/manga-babble-maker)へ保存する。

## 旧フォルダ撤去後の確認

- 公開保存先の`main`は`3edfaf975ce91fb1eadd6e228df3107b23b5fb8e`。ローカルの全178ファイルとGitHubのblobを照合し、未送信3コミットと追加資料78ファイルを含む保存を確認した。
- `manga-babble-maker`のローカルフォルダは撤去済み。ニャムル内のモデルが通常ファイルであること、上記SHA-256、旧フォルダ撤去後の実モデル読込と白紙画像の検出結果一致を確認した。
- `npm run bridge:check`成功。`rtdetr_model`はニャムル内を指し、RT-DETR・Baberu・WD・VLMの利用可否がすべてtrue。VLMなど、今回の旧Bubble Makerとは無関係の共有環境は変更していない。
- `npm run verify`成功。型検査400ファイル、Node 1,034件成功・3件skip、Python bridge 419件（50件skip）／doctor 18件（1件skip）／人体ポーズ45件（21件skip）。通常版・単一HTML版ビルドも成功。
- 既存の原稿・現行コードなど1,029ファイルのSHA-256は不変。利用者の既存の未commit差分も保持した。稼働中のサーバーは停止・再起動せず、既存の待受を維持した。旧フォルダの監視用ディレクトリハンドルも撤去後に残っていない。

ブラウザーでの新規取り込み操作と検出精度の再評価は未実施。今回の是正対象は、以前の指示に反して残っていた旧Bubble Makerへのモデル依存である。
