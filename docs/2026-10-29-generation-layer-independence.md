# 2026-10-29 生成画像とマスクの独立レイヤー化

基点: `2586a78`。正本 `Comic_image_Hub`。利用者の指示により、実作品フォルダーの読込修復、未合格だった画素比較2件の修正、全件検証・ビルドを完了した。

## レイヤーの扱い

- 生成画像は対象フォルダーの最上段へ追加する。あたり・既存画像・文字・目・固定を保持する。
- ネイティブ文字の非表示・固定を画像レイヤーへ継承しない。画像だけをVで紙面移動でき、パレットでフォルダー外へ取り出せる。ネイティブ文字と親フォルダーの配置ロックは保持する。
- 生成マスクは `PaintLayer.generationMask: true` を持つ通常のラスター1レイヤー。子を持たず、共通の `strokes`・目・固定・濃度・合成・名前・並べ替え・複製・削除・所属・座標変換・保存を使う。
- `PaintDocument.generationMask`、親マスクのグループUI、専用のstroke更新・選択状態を撤去した。`insertGeneratedPaintImage`、`movePaintEntry`、`PaintEditor.commit`、共通履歴とwriter/validatorへ集約した。
- 通常PNGからマスクを除外する。生成範囲はマスク自身の可視性・濃度・clip・消去を反映する。修正用画像では選択したマスクだけを最前面へ合成し、保存上の並び順を変えない。
- マスクをトーン化しない。ベジェペンは兄弟ベクターレイヤーへ描画し、マスクのラスターstrokeへベクター道具の値を保存しない。仮想あたりの画像化でも兄弟レイヤーを保持する。

## 作品フォルダーが開けなかった原因と修復

対象は利用者指定のテスト作品 `nyamuruテスト用シリーズフォルダ/no.1.5/.nyamuru/project.json`。

画像レイヤーに試用中の `generationMask: { enabled, strokes }` が残り、現在のboolean検証が拒否していた。開発データ方針に従い、このファイル内の文書属性1個とレイヤー属性1個だけを除去した。マスクを推測移行するアプリ経路は追加していない。

除去属性を戻すと修復前のJSONと完全に一致することを確認した。その他の文字・配置・レイヤー・画像参照・65件のasset記録は不変。37件の描画文書、実際のnative `load_project` と全65画像参照の検証が成功し、通常の4321画面で4ページの作品が開いたことも確認した。テスト作品の修復はrepository外のローカルデータ変更で、アプリのGit commitへ含めない。

## 画素比較2件の解消

- **グレースケール:** レイヤーの画素読取と合成先のCanvas Context設定を揃えた。パレットも最初のContext取得から `willReadFrequently: true` を指定する。PNG比較の復号先も同じ読取方式を使い、GPUへの再合成による丸めをエンコーダーの差として扱わない。原寸・ライブ・PNGの全RGBA完全一致を維持し、19項目成功。
- **余白追加後の縮小トーン:** Canvasの拡大縮小後に大きな原点を相殺すると、境界のfloat32丸めが変わっていた。既存の `mapPaintLayer` / `mapPaintStroke` で表示原点を座標から先に引き、Canvasには拡大縮小だけを渡す。確定・ライブ・マスク描画を揃え、トーン位相は文書座標のまま保持する。マスク・トーン・ベクター・3表現色の画像を含む19項目成功。

許容差を加えたり、画素一致のassertを緩めたりしていない。変換は描画用コピーだけに適用し、元のレイヤーや画像cropを書き換えない。
