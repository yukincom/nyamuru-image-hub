# Pythonの重さ・寿命の調査

2026-09-10。対象はComic Image Hubのbridgeと解析worker。当時併せて調査したKrea2は2026-10-21に終了し、専用の詳細記録を[経緯と構成](2026-10-21-krea2-trial.md)へ集約した。以下は共通処理の改善記録。

## 観測と限界

- 待機中のbridge PID20146はRSS 52,576KiB（約51MiB）。この一時点では大きくない。RSSは圧縮メモリやGPU allocationを含む総負荷ではなく、推論ピークの測定値でもない。
- ソース上の不要処理・保持経路は確認できたが、個々が先行失敗に寄与した量は未測定。コードの行数削減自体を大幅なメモリ改善と扱わない。

## 整理したもの

| 対象 | 原因と変更 | 確認範囲 |
|---|---|---|
| WD表情モデル | bridgeがONNX sessionを保持していた。bridgeと同じPythonの短命workerへ移し、終了後にVLMへ進む | 合成64×96画像で実WD成功、約0.65秒、終了後登録worker 0件。顔の解析品質評価ではない |
| worker起動 | ローカルVisionとMLXでPopen・JSON受信・終了処理が重複。共通化し、timeout以外の通信例外・shutdown登録競合でも終了を待つ | 実小型Python子プロセス、mockによるTERM→KILL、通信例外、登録競合、pipe close |
| 一時ファイル | 一括VLMの終了台帳に先頭画像しか登録されず、書込後に所有登録していた | 全画像を登録。書込途中・起動失敗でも全ファイルを削除する回帰テスト |
| 解析同時実行 | ページ解析とVLMが別lockで、異なるタブから重ねられた | HTTPのページ解析と4種類のVLM解析を同じlockへ統一。モデル/プロンプトは不変 |
| 資料の画像コピー | 内部処理でもPNG→Base64→PNGと往復。最大12枚を全部読んだ後に総80MiBを検査 | 検証済みraw bytesを直接渡し、読込自体も既存40MiB上限+1に制限。総量超過時はその場で中止 |
| HTTP画像の保持 | decode後もrequest辞書にBase64を保持 | 消費したimageをpopして推論中の余分な参照を残さない |
| 未使用API | 現行画面から呼ばれない生成準備・形状APIとTSラッパー、適用helper、専用テスト | 呼出し元を全追跡して削除。人物アクション補足、生成英訳、ブラウザ形状判定は残す |
| 接続確認 | checkコマンドまでサーバーの単一起動記録を取得し、稼働中は確認できなかった | checkは所有記録を取得・削除せず実行。モデル推論は起動しない |

削除したコードはGitのbase `a5bee70`から復元できる。元画像・作品・モデル・保存済み生成記録は削除していない。

## 今回変えず、相談する点

1. **アプリ全体での排他**：この調査で追加したlockはbridge内の画像解析だけ。当時はアプリ全体のAI処理の排他を検証していない。現在の排他範囲は現行コードで確認し、別アプリのモデルを勝手に停止しない。
2. **人物資料一括の速度と精度**：12枚なら顔・身体比較各12回と集計2回、最大26回のVLM推論。各画像を二度前処理する部分もある。比較回数・同時入力枚数を減らすなら特徴統合の品質検証が必要。今回は回数・prompt・画像の切り抜きを変えていない。

WDの縮小前の正方形化、顔/身体の共通前処理化、worker内部の一時JPEG所有範囲も追加改善候補。画像の境界画素・EXIF・文字マスクを変えない比較と例外テストをそろえて別の小さな変更に分ける。MLX応答は文字列・統計であり、モデル/KVを抱える根拠はないため、効果未確認の一律`gc.collect()`や`del response`は追加していない。

## 検証

- 重点Pythonテスト：実画像解析環境で144件すべて成功。小型実子プロセス以外のVLM/画像生成は起動しないテスト。
- 新規launcher所有権テストを含む重点Nodeテスト：58件成功。
- 実WD worker：合成画像1枚で成功し、子プロセス終了・bridgeへのモデル非保持を確認。
- 稼働中のbridgeを維持したまま`npm run bridge:check-vlm`成功。既存RT-DETR/OCR/VLM/WDの利用可否と配置を再確認。
- 全体 `npm run verify` 成功：Astro 160 files/診断0、Node 510成功/3skip、bridge 242件/31skip、doctor 18件/1skip、通常版と単一HTML版build成功。最初の制限環境ではHTTPテスト2件がlisten EPERMになったため、許可された環境で再実行した。
