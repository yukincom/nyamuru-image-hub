# 通常画面のHTTP 500復旧

2026-10-17。名称復元後に確認した`http://127.0.0.1:4322/`のHTTP 500を、利用者の指示に基づき復旧した。作業開始時のHEADは`827c0cf`。

## 原因と処置

- エラーを返していたPID `26204`は9月29日に起動されたAstroの直接実行プロセスで、起動コマンドは存在しない旧フォルダ`Comic Image Hub`を参照していた。現在のフォルダは`Comic_image_Hub`。
- `.astro/dev.log`には`Failed to load url @astrojs/preact/server.js`が記録され、スタックも旧フォルダを参照していた。現行環境では対応する`node_modules/@astrojs/preact/dist/server.js`とpackageのexport指定が存在する。
- 旧ログを`.astro/dev-before-500-fix-20261017.log`へ保存したうえで、当該PIDだけをSIGTERMで終了した。
- 現在のフォルダから既存の通常起動経路を使用し、同じURLで再起動した。

```bash
npm run dev -- --port 4322 --host 127.0.0.1
```

アプリコード、依存パッケージ、モデル、作品データは変更していない。別のサービスを一括終了せず、既存の未コミット変更も保持した。フォルダ移動前に起動したサーバーが残っていたことによる実行状態の不整合で、現行の通常起動経路で解消した。

## 確認結果

- 新しい画面サーバーPID `28009`の作業ディレクトリは現在の正本で、`4322`と起動管理用の`8786`を待ち受けている。
- トップページはHTTP 200。`8786/api/health`も`ok: true`、`nyamuru-image-hub-bridge-supervisor`を返した。
- 一時配布サーバーを使わず、通常URLをブラウザで開いて「Nyamuru Image Hub」のタブ名と「NYAMURU - Image Hub」のヘッダーを確認した。
- 保存されていたページの画像、フキダシ、レイヤー、編集欄まで表示された。作品の編集・保存操作は行っていない。
- 画面を開いたまま残し、通常サーバーを継続稼働させた。確認画像はGit対象外の作業成果物`output/runtime-recovery-20261017/nyamuru-restored.jpg`に保存した。

コード変更がないため、今回はHTTP応答と実ブラウザ表示を検証対象とした。画像解析、生成、モデル切り替えの再検証は行っていない。
