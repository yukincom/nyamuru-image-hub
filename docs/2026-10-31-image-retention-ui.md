# 画像の保持と解放：編集画面での検証（2026-10-31）

`cb9ec75` の画像回収を、正本の編集画面に合成PNG 4枚（A～D、各768×512）を実際に取り込んで確認した。最後に残ったのは、編集中の作品とは別のシリーズの資料画像1枚（332バイト）だけだった。

| 操作と合格条件 | 観測結果 |
|---|---|

| Aの取り込み前までUndoしてBを読む。Redo側しか参照していないAは消える | Undo 0／Redo 2からUndo 1／Redo 0へ。保持はBと資料の2枚、9,114バイト。Aなし |
| Cを保存直後・作品反映前で一時停止して本体の回収処理を呼ぶ。Cが残り、再開後に配置できる | 取込中1・配置1・保持3枚、18,306バイトのまま。再開後は取込中0・配置2、BとCの配置を確認 |

再現には `node node_modules/vite/bin/vite.js --config tests/imageRetention.vite.mjs` を起動し、`http://127.0.0.1:4347/tests/imageRetention.browser.html` を開く。異なるPNGを用意し、表の順にヘッダーの「画像読込」、配置画像の「配置を削除」、「元に戻す」「やり直す」を操作する。長い取り込みは観測欄の「次の画像保存を一時停止」を押してから読み込み、「現在の参照で回収を要求」「保存を再開」で確認する。ト書きの編集は、履歴がまとめられないように1回ずつ区切る。

専用originで起動時の作品とシリーズ資料を用意し、Viteの検証設定だけで観測と保存待ちを挿入した。画像選択・デコード・配置・履歴・回収には本体を使用。通常画面のコード・利用中の作品は変更していない。数値は画像ストアが所有するBlobの合計で、ブラウザー全体のヒープ、GPU、OSのメモリ返却量を表さない。別PCのLAN通信・実モデル・全件テスト・ビルドは今回の対象外。
