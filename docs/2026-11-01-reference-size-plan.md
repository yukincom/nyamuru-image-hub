# ネーム・3D・設定画の保存寸法：段階実装計画

状態：仕様と計画のみ。各段階は個別に実装・検証・コミットし、次へ進む前に実際の編集表示を確認する。今回のコミットではコード、テスト、既存作品、ComfyUIの登録内容を変更しない。

仕様の正本は[人物・文字あたりの保存と表示](ANALOG_FIGURE_CROPS.md)、[人物3枚参照の保存寸法](COMFYUI_WORKFLOW_SPEC.md#人物3枚参照の保存寸法実装目標)、[設定画の台帳項目](../src/content/nyamuru-data-model-v10.md)。対象は新規取込・新規確定の参照画像。印刷原稿、通常の手描きレイヤー、3Dモデル本体、既存の保存画像は変換対象に含めない。

| 段階 | 実装すること | 次へ進む条件 |
|---|---|---|
| 1　人物のネーム | 紙面の向きを反映して元解像度で検出・切り抜き、人物照合と表情読み取りに渡す。読み取り終了後、保存用PNGだけ縦横20%にし、元の人物枠に表示する。 | 同じ原画で人物・表情の解析に渡るのは20%化前の画素寸法である。保存済みPNGの各辺が20%で、コマ上の位置・向き・表示枠は変わらない。 |
| 2　文字あたり | OCR・行のまとめ・元画像でのレベル補正を先に済ませる。人物と同じ寸法規則で原字参照だけを保存し、原字レイヤーへの変換でも同じPNGを使う。 | 本文・改行・縦横書き・フキダシ・文字枠・表示状態が維持される。細い字の見え方を比較し、再保存・再読込後も二重に縮まない。 |
| 3　3D確定画像 | ポーズ確定時に不透明な撮影PNGを縦横20%にして人物の確定データに紐づける。既存の画像資産の保存・読込を利用し、コマに置く寸法と保存画素数を分ける。image1はそのPNGを表示・送信する。 | 確定・開き直し・再編集でポーズ・カメラ・見切れが一致し、取り消しは前の確定画像を保つ。**下記の生成寸法を決め、準備から採用まで確認するまでは有効にしない。** |
| 4　キャラクター設定画 | 入口で元画像の幅と高さを判定する。一辺でも超過なら、そのファイルの登録を止める。上限値と実寸を知らせ、利用者がリサイズしたファイルを選び直せるようにする。 | 幅のみ超過、高さのみ超過、上限ぴったり、上限未満を確認。拒否画像の本体や台帳項目は作らず、既登録資料・人物との対応を保持する。上限内の画像は再縮小しない。 |

## 実装時に確認する経路

- **ネームと文字：** `App.tsx` の作品作成は `prepareDetectedFigureCrops` / `prepareDetectedTextCrops` の結果をIndexedDBへ保存し、設定によって同じ画像を永続保存する。その後、人物照合・演技解析は `loadFigureCropAsset` から画像を読み直す。先に小さなPNGを保存して同じ処理を続けると、解析にも小さな画像が渡る。解析には元画像から対象領域を一時的に取り出し、永続化するのは縮小版だけにする。全ページの原寸切り抜きをメモリにためない。
- **原稿表示・保存：** `sourceBBox` は正立した元ページでの領域、人物・文字の配置枠は原稿上の位置、PNGの幅・高さは画像実体に属する。丸めた画素数を5倍して位置や枠を復元しない。`prepareGuideLayer`、文字原本レイヤーの分離、作品フォルダへの保存と再読込で、拡大済みコピーを格納しないことを確かめる。縮小・保存失敗時は取込を確定せず、再試行できる原画を残す。
- **3Dと生成：** 現在、生成画面の確定PNGはダイアログ内の一時状態。保存を追加するときは人物・コマ・撮影条件との対応、再確定時の差し替え、失敗時の復元を一緒に扱う。`qwen_generation.py` の受付はimage1が出力と同じ寸法か検査し、登録グラフはimage1から出力・切り抜き寸法を取る。採用時もニャムルが候補画像の寸法を照合する。検査だけを外したり、グラフにもう一段20%縮小を足したりしない。
- **設定画：** `imageFileToPng` は現在、最長辺4096pxを超えると登録前に自動縮小する。この入口で選択ファイルの向きを考慮した実寸を先に検査し、超過時は画像変換・アップロード前に止める。通常版・ブラウザ保存・bridgeの直接登録で制限が食い違わないようにする。上限内のPNGへの形式統一は画素寸法を保つ。

## 確認例と未決事項

- 1000×500pxの人物、101×49pxの原字、極細の領域を使う。保存寸法はそれぞれ200×100px、20×10px、最小1px。回転を含む原稿で、編集枠の四隅・移動後の位置・再読込したPNG寸法を比較する。保存前後の参照PNGと作品全体のバイト数は別々に測る。原稿全体が1/25になることを合格条件にしない。
- **第3段階の提案：** 下書きなら、生成候補も幅・高さ各20%の寸法で受け取り、同じ物理サイズのコマへ配置する方法がある。印刷dpiと原稿の座標はそのままで、下書きを原寸出力と表示しない。一方、印刷解像度の出力が必要なら、参照画像の寸法と出力をグラフ側で独立させる必要がある。どちらを採るかは未決定。印刷dpiの値を書き戻すだけでは線の精細さは増えない。
- **第4段階の未決事項：** 幅・高さの上限値。例えば4096×2186pxの多面図では、一枚に顔や服が複数並ぶ。上限候補を比較するなら、利用者が縮小したコピーで最小の顔・襟の線が読み取れるかを確認する。既存の4096pxを自動的に新上限としたり、登録済みの設定画を勝手に縮めたりしない。
- **確認の境界：** まず画素寸法・配置・保存・送信値を局所テストする。読み取り精度は元原画を使った実例、画質は画像を見て評価する。ファイルサイズや送信順のテストでは画質まで保証しない。実生成・既存作品の再取込は今回行わない。
