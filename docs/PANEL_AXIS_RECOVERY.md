# コマ境界の軸別補正（2026-09-07）

## 原因と修正

`infer_panel_shapes_from_segments` は横方向・転置した縦方向の両方で境界を追跡し、傾きが強い候補を採用する。転置側の候補には列全体の左右の外接範囲も入るため、段ごとに縦境界がずれる原稿で、そのずれが消えていた。後段のコマ間隔補正で上下の境界が同位置になる。

横境界の候補を採用するときは、その上辺・下辺の直線を各RT-DETR矩形の左端・右端で評価する。列全体の幅も、独立した縦境界候補の幅も流用しない。横境界の傾きと各コマの横幅を両立する。平行・非有限・範囲外・反転した形状になる場合は元の検出矩形へ戻す。候補選択、読み順、コマ数、人物・OCR処理、既存作品の保存データは変更しない。

通常の `tests/test_scanner_bridge.py` には、ずれた縦境界＋傾いた横境界、左右4コマ、斜め枠、退化形状の合成テストを含む。追加の画像テストは既存のローカル資料・環境を明示した場合だけ実行し、未指定時はskipする。

```sh
NYAMURU_TEST_ONE_IMAGES='/absolute/path/to/テスト画像' \
NYAMURU_TEST_VISION_ROOT='/absolute/path/to/.local-vision' \

```

Vision rootは `.venv/bin/python` と `models/rtdetrv4-x-manga109s_v2/model.onnx` が既にある環境を指定する。取得・インストールは行わない。画像テストは橋渡し処理からフロント側のコマ間隔補正まで検証するが、稼働中ブラウザの作品を書き換えない。

Python側の変更なので、稼働中bridgeへ反映するにはbridgeの再起動が必要。保存済み・編集中の作品のコマ形状は自動更新しない。
