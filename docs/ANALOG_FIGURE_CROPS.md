# アナログネームの人物・文字あたり画像仕様

## 目的

紙または画像のネームは、人物・表情・文字の読み取りに必要な解像度で解析する。読み取り後は、編集に使う人物あたりと文字あたり（原字参照）の切り抜きだけを小さく保存し、元の原稿位置・大きさで表示する。

この節の保存寸法は実装目標。[段階計画](2026-11-01-reference-size-plan.md)に実装状況と確認条件を記載する。

このデータはNyamuruのOMNYとは分離したローカル中間データとして保持する。将来、CLIP STUDIO PAINTなどへ接続するアダプターは、この中間データを各アプリ固有のレイヤー表現へ変換する。

## 対象範囲

- RT-DETRが検出した `body` / `face` 領域を使用する。
- 読み込み時にユーザーが指定した0° / 90° / 180° / 270°の向きを反映して切り抜く。
- 人物の切り抜き画像は色変換、白の透明化、不透明度変更、描画モード変更を行わない。
- 文字は文字領域をまとめて切り出し、既存のレベル補正を元解像度で行う。OCR本文・文字組み・読み順・原字参照の表示状態は画像と独立して保持する。
- 人物同定・表情や演技の読み取りに使うのは縮小前の切り抜き。解析用の原画は作業中だけ利用し、編集用画像として二重に保存しない。

## データ構造

人物あたりには、次のローカル専用メタデータを関連付ける。

- `sourceRegionId`: 解析元ページ内で人物領域を一意に識別するID
- `assetId`: IndexedDBに保存した切り抜き画像のID
- `sourceBBox`: 正立させた原画上の正規化座標
- `detectionSource`: `body` または `face`
- `confidence`: 検出器から得られた場合だけ保存する信頼度
- `draft`: 常に `true`
- `userEdited`: 人物あたりの位置・大きさをユーザーが変更した場合に `true`

人物・文字とも、正立したページ上の切り出し位置、原稿上の配置枠と保存PNGの画素寸法を区別する。配置枠をPNGの幅・高さから逆算しない。切り抜き画像本体はブラウザのIndexedDBへ保存し、作品フォルダや原画参照の永続保存が有効な場合も同じ縮小済み画像を使う。OMNYのコピー、YAML表示、YAML書き出しには、上記メタデータと画像本体を含めない。

## 生成と表示

1. 原画の向きを確定し、元の解像度で領域検出・文字認識・人物と表情の読み取りを行う。画像全体を先に縮めてから解析しない。
2. 読み取りが済んだ切り抜きの幅・高さをそれぞれ60%にする（各辺は四捨五入、最小1px）。例：正立後の切り抜きが1000×500pxなら、保存PNGは600×300px。画素数は端数を除いて元の36%だが、PNGのバイト数は内容によって変わる。
3. 編集画面では、そのPNGを元の配置枠いっぱいに描画する。画面用に拡大した別画像は保存しない。人物・文字あたりを動かした後も、再表示・保存・開き直しで位置や大きさは変わらず、画像を再び60%に縮小しない。
4. 編集できる本文・ベクターのフキダシ・人物の属性はそのまま扱う。縮小は新しく取り込むラスター画像に限り、スキャン元のユーザーファイルや既存作品を一括変換しない。

取込用の一時原画を解放するのは、読み取りと保存が成功し、ユーザーが「編集開始」を確定した後。失敗した場合は再試行できる状態を保つ。利用者が選んだ元ファイル自体は変更しない。

## コマ合体時の重複整理

コマ合体で複数の人物あたりが同じコマへ集まる場合は、次の順で重複を整理する。

1. `sourceRegionId` が同じものは同一検出領域として扱う。
2. IDのないデータは、人物枠の重なりが十分に大きい場合だけ重複候補とする。
3. 残す優先順位は、ユーザー編集済み、`body`、信頼度、安定した小さいIDの順とする。
4. 異なる人物が近接しているだけの場合は削除しない。

コマ番号や人物配列の添字だけを重複判定に使わない。

## 将来のCLIP STUDIO PAINT接続

CLIP STUDIO PAINT側の仕様が確認できた段階で、ローカル中間データから次を生成する。

- 人物切り抜き画像を配置したレイヤー
- 人物あたりの位置・大きさ
- 下書きレイヤーフラグ

白の透明化、不透明度、乗算、グレースケール変換はNyamuru側では固定せず、接続先またはユーザーの作業設定へ委ねる。
