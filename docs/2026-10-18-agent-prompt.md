# エージェントの役割と指示文（確認用）

2026-10-18。利用者が指示文と接続案を承認済み。この全文を変更せず実LLMへ接続した。先に提示した「操作結果を言い直すだけ」の案は採用しない。

## 接続の考え方

- 簡単な操作は既存のBERT分類・引数確認・アプリ操作を使う。
- 会話、相談、形状調整などは、会話履歴と現在の原稿を理解するLLMへ渡す。
- LLMには選択中のフキダシを読む、形・位置・大きさ・ベジェ・しっぽを変更する、結果を読み直すツールを接続する。
- BERTの分類名だけで「考える操作はできない」と打ち切らない。すでに実行した簡単な操作をLLMがもう一度実行しないよう、実行済みの結果を渡す。
- 名前・口調はプロフィールとして渡す。顔画像は表示用で、会話へ送らない。

## 編集ツール

現在のポップアップから以下を利用できる。LLMはツールを提案し、画面側が現在の選択・revision・編集可否・引数を検証して適用する。

| ツール | 渡す内容・実行内容 |
| --- | --- |
| `editor_inspect` | 現在ページ、選択中のフキダシ、本文・話者・形・素材・ベジェ点・実効bbox・しっぽ・ロック状態、原稿のrevisionを読む |
| `editor_bubble_edit` | 読み取ったrevisionと対象に対し、輪郭プリセット／素材／ベジェ全体または点ごとの差分、bbox、しっぽの指定箇所だけを変更する。1回のUndoで戻せる |
| `editor_inspect`（変更後） | 適用された値を読み直し、操作が成功したか確認する |

画面の既存関数を使い、別ファイルに原稿を書き出すCLIは経由しない。待機中に原稿・選択が変わったら古い対象へ適用しない。ペイントや文字の編集中、生成中、非表示・ロック中は現在の編集ゲートに従う。

旧editor agentの状態取得・revision・適用ゲートは参考にできるが、旧実装を丸ごと戻さない。現在の38素材、ベジェ3〜64点、人物枠外へのしっぽ指定、見切れ表現の仕様に合わせる。

## 例

「この吹き出しの上側だけ丸くして」→現在の選択とベジェ点を読む→上側の点・ハンドルを編集→適用結果を読む→設定したキャラクターの口調で短く返す。

「しっぽも少し短くして」→会話と現在の選択を読み直す→既存のしっぽの先端を調整→結果を確認する。

「このセリフどう思う？」→会話として答える。編集を頼まれていなければ本文は変えない。

## 引数と結果の検証

- 編集は `{revision, target, changes}`。`changes`内は`preset`、`material`、`bezier`、`node_updates`の輪郭指定のうち一つと、`shape`、`bbox`、`tail_mode`、`tail_point`。省略値を埋めて推測しない。
- `node_updates`は既存ノードの0始まりindexと変更項目だけを受け取り、未指定の座標を保持する。変更後も点と制御点が0〜100内にあることを検証する。
- `tail_point`は紙面mm、`tail_mode`は`auto`または`none`。同時指定不可。内部では既存の話者bbox相対座標に変換する。
- 1リクエスト8ラウンドまで。同じエラーが3回続いたら停止する。不正な階層を自動的に補正しない。
- BERT側で処理した操作の表示は、その操作の実結果を優先する。失敗・未知ツール・無変更をLLMの成功文で上書きしない。
