# 漫画仕上げ仕様

2026-11-02。生成候補の透過・複数採用・未採用削除と自作フォルダーの入れ子は実装済み。漫画仕上げ処理は未実装。人物生成は原稿上で比較できる透過画像を渡す。漫画仕上げは、編集画面で同じコマのラスターレイヤーを1枚または複数選んで実行する。

## 制作の順序

| 順序 | 操作と結果 |
|---|---|
| 1 | ニャムルは既存の人物生成ワークフローで、均一な緑背景（#00FF00）の候補を異なるシードで5枚生成する。人物の線・ベタ・陰影、画風、表情は既存の設定欄に従う。 |
| 2 | ニャムルのコードで5枚すべての緑を抜き、生成画面に透過済みの5枚を表示する。比較する画像と、後で原稿へ追加する画像は同じ透過PNGを使う。 |
| 3 | 5枚が揃い、利用者が1枚以上を選ぶと採用を確定できる。選択分を生成元画像のフォルダーへ1候補につき1レイヤーとして追加し、「生成 01」「生成 02」…と初期名を付ける。採用分がすべて追加された後に未採用分を削除する。 |
| 4 | 利用者は原稿上で周囲の絵と見比べる。採用した候補の表示・非表示・移動・削除、透明部分への塗り足しは通常の編集操作で行う。このまま完成画像として使うこともできる。 |
| 5 | 同じコマのレイヤーパレットで、仕上げたいラスターレイヤーを1枚以上選び、ツールパレットの「漫画仕上げ」を一度実行する。生成画像、読み込み画像、手描きのラスターを組み合わせて選べる。 |
| 6 | 仕上げ直前の入力から人物の範囲を取得し、MangaScreenの白背景をコードで透過する。人が塗った肌・服の白、内側の透明な隙間を保持し、仕上げた輪郭の近傍だけで境界を整える。 |
| 7 | 入力レイヤーごとに1個の「仕上げ✨」を作り、それぞれの元の親・位置・重なり順で置き換える。各フォルダーに線・ベタ・グレーの陰影・白下地を格納し、ニャムルが陰影から網点を描画する。 |

## 透過候補の採用と破棄

採用画面は透過候補の比較・複数選択・レイヤー追加を担当する。生成や選択操作だけでMangaScreenは動かない。未完了時や選択が0枚の間は採用を無効にし、選択を変えている間は全候補を保持する。入力の参照順はimage1が3D、image2が設定画、image3がネーム。参照寸法、生成寸法、配置枠、解像度、CFGは既存の人物生成経路を使う。

たとえば候補2と4を確定した場合、元画像のフォルダーに透過レイヤーが2枚入る。両方の追加が成功してから、候補1・3・5について、ニャムルで保存した緑背景画像・透過画像と、同じジョブがComfyUIに保存した該当候補の出力実体を削除する。ジョブと候補番号に対応する出力だけを扱う。参照資料や他のジョブの出力はそれぞれの所有者が管理する。

「生成 01」などの番号は編集画面に実際に追加したニャムル生成画像の連番。最初の追加が候補2と4なら、初期名は「生成 01」「生成 02」となる。候補プレビュー、未採用候補、外部画像の読み込み、手描きレイヤーは採番対象外。利用者は通常の名前変更で自由に改名できる。保存・再読込やUndo/Redoでは、その状態に記録された名前とIDを復元する。追加のRedoで番号を新しく取り直すことはない。

追加失敗やキャンセルの時点では比較・再試行できる状態を保つ。既存の採用記録に採用集合と破棄の結果を記録し、再表示・再試行で候補を重複追加しない。破棄済み画像の欠落は当該ジョブの完了状態と区別する。確定後のUndoは原稿への追加を戻す。破棄した未採用ファイルの復元は対象外とする。採用済みの別候補を整理する時点と方法は利用者が決める。

## 漫画仕上げと輪郭

ツールパレットの既存の空き位置に、他の道具と同じ単色の✨型アイコンを置く。既存のボタン部品・寸法・線幅・色・操作状態を使う。画面には操作名・調整項目・比較プレビューを置き、操作説明はマニュアルに記載する。画像の取り込み・レイヤー選択・ドラッグ・トーン表示は既存経路を使う。

仕上げを開いた時点で、選択した各ラスターの**現在の描画内容・透明度・紙面上の配置**を取り込む。対象に塗り足した場所は描画側、消した場所や腕の間の穴は透明側になる。入力範囲は同じコマで選択したレイヤーに限る。複数選択でも実行と作品への確定は各1操作とする。処理中の選択変更によって別の画像へ結果を適用することはない。

MangaScreenへは白下地に合成した処理用画像を渡し、入力の透明度を別に保持する。コードは明らかに透明な外部と穴を透過、明らかに不透明な内部を維持し、境界帯だけで仕上げ結果の輪郭に合わせる。同じ境界を線・ベタ・陰影・白下地に適用する。白という色だけで肌・服・白抜き線を消したり、元のぼんやりした透明度をそのまま掛け戻したりしない。白背景の全画面除去はこの工程に適さない。

透過範囲の手掛かりがない完全不透明の外部画像は、入力どおり背景を含めて仕上げるのが提案。利用者が先に背景を消した画像は同じ境界処理を使える。

## 仕上げフォルダーと履歴

仕上げフォルダーの初期名は **「仕上げ✨」**。元のレイヤー名は付加しない。利用者はレイヤーパレットで任意の名前に変更できる。識別には既存のIDを使うので、同名のフォルダーも別の対象として扱える。

同じコマで2枚を選んだ場合は、元レイヤーごとに別々の「仕上げ✨」が1個ずつできる。各入力を個別にレンダリングし、手直し済みの透明範囲も入力ごとに使う。各結果は元レイヤーの親フォルダー・紙面上の位置と大きさ・重なり順を引き継ぐ。選択した2枚の間に未選択の絵があれば、その絵は結果の間に残る。

| 上からの順序 | 内容 |
|---|---|
| 線 | 整えた輪郭と内側の線。必要な白抜きを保持する。 |
| ベタ | 黒い面。 |
| 陰影 | MangaScreenが分離した網点化前のグレーを保持する。ニャムルの画像トーン機能がその濃淡を使う。 |
| 白下地 | 仕上げた人物の内側の白。人物の外と透明な隙間は透過する。 |

MangaScreenの出力は線・ベタを明瞭にし、陰影をグレーに分けたところで完了する。網点の描画はニャムルの既存トーン機能だけが担当する。同じ線数・角度を使うときは紙面上の網点の原点を共有し、異なる位置に置いた人物や切り出し寸法の違う画像でも、同じ紙面座標で網点が揃うようにする。グレーの原画を保持するため、後から線数・角度を調整できる。

選択分すべての仕上げ結果の適用と処理前レイヤーの削除を1回の編集操作にまとめる。Undoで手直し済みの入力を復元し、Redoで同じ仕上げ結果を復元する。途中で失敗した場合は適用前の作品を保つ。

**レイヤーパレットの削除は共通の編集履歴で扱う。** 通常の描画・読み込み画像・生成画像・仕上げ結果・フォルダーとその中身を含め、削除はUndoで復元、Redoで再適用できる。削除済み項目を復元できるUndoまたはRedoの状態がある間は、画像実体・名前・所属・順序・編集内容を保持する。現在の作品とUndo/Redoの両側から最後の参照がなくなった時点で、専有する保存データを既存の回収処理で完全削除する。同じ画像を別項目や資料が使っている場合は、その参照が残る間は実体を保持する。作品へ追加しなかった生成候補の破棄は先の採用手順に従う。

完全削除には、削除した項目だけが使っていたニャムル管理の画像と、当該生成ジョブに対応する専有の出力複製も含める。外部から読み込んだファイルの原本は利用者が管理する。

## 自作フォルダー内での置き換え

自作フォルダーの中にあるラスターにも、元のレイヤー1枚につき1個の「仕上げ✨」を作る。各フォルダーはその入力の**直接の親の、同じ兄弟位置**に入る。紙面上の座標・大きさも入力ごとに引き継ぐ。異なる自作フォルダーから選んだ場合も、それぞれの親の中で置き換える。

例えば自作フォルダー「人物案」の中で、パレットを上から見た順序は次のようになる。A・Bは内部で区別する2個のIDで、画面にはどちらも「仕上げ✨」と表示する。

| 操作 | 「人物案」の直下に並ぶ項目（上から下） |
|---|---|
| 仕上げ前 | ハイライト、生成 02、効果線、生成 01、あたり |
| 生成 02と生成 01をまとめて仕上げた後 | ハイライト、仕上げ✨（A）、効果線、仕上げ✨（B）、あたり |
| Undo | ハイライト、生成 02、効果線、生成 01、あたり |
| Redoして保存し、作品を開き直した後 | ハイライト、仕上げ✨（A）、効果線、仕上げ✨（B）、あたり |

各「仕上げ✨」を展開すると、上から線・ベタ・陰影・白下地の順になる。空フォルダーも1項目として位置を保持する。

### 移動・表示・履歴

- 既存のレイヤーパレットで、行の中央へ落とすと対象フォルダーの直下の最上段へ、行の上下へ落とすとその項目と同じ親の前後へ移る。直下から外に出したい場合は親フォルダー行の上下、または既存の最上位への移動先を使う。この規則はレイヤーとフォルダーに共通とする。
- フォルダーを移動すると、子孫全体がまとまって移り、内部の順序を保つ。同じ描画対象内の所属変更は紙面上の座標を保つ。既存の移動操作で別の描画対象へ渡すときは、その座標変換を各子孫レイヤーに1回だけ適用する。
- 自分自身や自分の子孫はフォルダーの格納先にできない。無効なドロップ、取消し、同じ位置へのドロップは履歴を増やさない。
- フォルダーの非表示・手動ロックはすべての子孫に継承する。子自身の目・ロックの設定は保持し、親を再表示・解除したときに戻す。パレットを折りたたむ操作は行の表示だけを変える。
- 「フォルダーを解除」は直下の項目を1段だけ親へ戻し、元のフォルダーが占めていた位置に同じ順で並べる。子フォルダーの中身はまとまったまま残る。削除は対象と子孫をまとめて既存のUndo/Redoで扱う。
- 一括仕上げ、フォルダー移動、解除、削除はそれぞれ1操作を1履歴とする。Undo/Redoは親・兄弟順・名前・表示・ロック・紙面位置・画像参照を復元し、仕上げ結果を再生成しない。

### 保存と再読込

自作フォルダーと「仕上げ✨」は同じ保存形式を使う。既存のレイヤー配列を描画順（下から上）の正本とし、各レイヤーは直接の親フォルダーID、各フォルダーは自身のIDと任意の直接の親フォルダーIDを持つ。親指定がないフォルダーは描画対象の直下にある。同名のフォルダー、空フォルダー、改名したフォルダーもIDで区別する。

通常の作品保存で、深い階層を含む所属・順序・各画像の配置と資産参照を一緒に書く。作品を閉じて開き直した時は、保存時点のパレットの親子関係と重なり順、キャンバス上の位置・見え方を復元する。編集時のUndo/Redoと、保存した現在状態の再読込をそれぞれの既存経路で扱う。
