## 目的

利用者が選んだ配布CC0 30件と、PNGを基に確認した日英文からポーズ一覧を作る。研究用68件は履歴・参考素材として保持する。利用者がBlenderで制作した共通素体を完成させ、大まかな姿勢を再現する骨のtransform、参照画像、日英文を本体の `.human_pose/` にまとめる。ニャムルで単純なポーズ絵から選び、利用者がポーズの文章を調整し、3Dでは人物の配置・向き・カメラを調整する。画角・アングル・向きの説明を撮影設定から作成し、既存のQwen画像生成へ渡す。

### 初期パイプラインと2つの送り方（2026-10-08・方針確定）

操作の共通部分は `大まかなポーズを選択 → 3Dで配置・向き・カメラを調整 → ポーズの文章を利用者が編集 → 送り方を選択 → 全指示を確認 → 英文化・生成`。2026-10-11の追加指定により、3Dの線骨格をマーカーで調整する操作と、モーションの時点を選ぶ操作を含む。文章編集と骨格編集は自動連動させない。

| 表示名 / 保存値案 | 送るポーズ指定 | 主な用途 |
|---|---|---|
| プロンプトで送る / `prompt` | 利用者が編集したポーズ文。ポーズ用の撮影画像は添付しない | 大まかな3Dとは異なる細かな姿勢を文章で指定する。初期選択 |
| 撮影画像で送る / `image` | 確認した3Dの撮影画像をポーズ参照として添付 | 撮影した単純な姿勢でよい場合。画像と矛盾する編集済みポーズ文は送らない |

人物の設定画、表情、画風、目線、撮影設定から得たアングル・レンズの説明、透過等は共通の入力。これはポーズの送り方であり、既存Qwenの新規生成／paint編集のmodeとは別に保存する。モード切替で日本語の編集値を消さず、画像モードでは文章モード用の詳細なpose指示を送信対象から外して一覧で示す。文章を3Dへ自動反映したと見せない。

3Dは文章作成と構図決めの下絵であり、採用30件の指先まで写真へ一致させることを初期条件にしない。素材制作時は出典と大まかな姿勢・接触を照合し、この利用者が確認したものを確定座標として保存する。共通素体1体へ保存した姿勢を適用して呼び出し、ポーズ済みモデル30体を必須の保存単位にしない。

背景で選んだ床・座面と正面方向への配置は、一回ずつ実行する補助として実装した。姿勢変更やモーション再生中の自動接地、任意の椅子へ関節を自動適応させる機能、全面的な衝突回避、ネームからの自動3D化、人物フォルダー単位の一括生成、背景の前後分離撮影は将来拡張とする。30件の共通素体への登録・全頂点検証は完了。生成への適合評価はP6に残し、P5の生成経路には代表素材から用いる。

人物設定には「女性／男性／中性」の性別欄を設け、ポーズ英文の代名詞と動詞を選択値に合わせる。取り込んだ素体・派生素材には元のキャラクター名を残さず、`human_base`、`human_rig` などの汎用名を使う。利用者の元ファイルは保存したまま、派生先で作業する。

初心者が何をどこへ書くか分かるよう、コマ情報の人物欄を用途別に分ける。現行の「アクション」の位置を「表情情報」とし、その下に「ポーズ検索」「ポーズプロンプト」「アングル説明」「レンズ指定」「被写体の目線」を並べ、ポーズの送り方を選べるようにする。ポーズ選択で日本語の文を入力し、利用者が微修正できる。アングル・レンズはP5で撮影設定からの変換を扱い、被写体の目線はカメラから推定せず独立した入力にする。

生成前に、表情情報を含む各欄と、人数・人物参照・外見保持・画風・描写範囲・出力形式等の自動指示を一覧で確認する。利用者が確認した後、文章モードではポーズの日本語変更分だけを基準英文へ反映し、両モードで送信する残りの日本語を英訳する。変更のない基準英文と固定英文は保持する。

### 3Dモデルを紐付けておく意図（2026-10-08・利用者メモ）

利用者は「もしかすると鶏肉うまいさんが落書きのポーズを3Dモデル化する技をそろそろ公開するんじゃないか」と期待している。将来、ネームに描いたポーズをそのまま3Dへ落とし込めるようになった時に接続できるよう、今の段階から画像・ポーズプロンプト・3Dモデルを紐付けたベースデータを用意しておく、という意図がある。既存のポーズを選ぶ用途に加え、ネーム由来の3Dポーズを受け入れるための下地にもしたい。

これは利用者の期待と設計意図の記録であり、技術の公開予定・時期・仕様を確認した情報ではない。P1〜P7はその公開を待たずに進められる計画とする。

### 将来技術の導入後に目指す使い方

利用者が目指す中心の操作は、ネームから推定した3Dポーズを確認・修正して使う流れ。ポーズ検索は、複雑ではない単純なポーズを選びたい時の補助として利用する。

1. 新規作成時のネーム読み取りで、人物ごとのポーズを推定して3Dモデル化する。
2. 推定した3Dポーズを対応するコマ・人物へ紐付けて読み込む。
3. コマ情報の「ポーズ検索」の隣に「ポーズチェック」を置き、読み込まれた推定ポーズを3Dで確認できるようにする。
4. 推定が合っていれば採用する。合わなければ、3Dモデルを直接編集するモード、または別のポーズイラストを渡して再ポーズする操作へ進む。
5. 修正・再推定したポーズを再び確認し、その人物の生成に使う。単純なポーズでよい場合は検索から選んで置き換えられる。

この流れは将来の拡張方針であり、初期P1〜P7の完了条件には含めない。公開技術の仕様を確認して具体的な接続方法を計画する。今のベースデータは検索catalogだけを前提とせず、ネーム由来・別イラスト由来・手動編集のポーズも、同じ「人物の現在のポーズ」として扱える下地にする。

## 共通の設計判断

1. **ポーズと他の指定を分ける。** 骨格の向き、関節、重心、接触、頭の向きはポーズ。視線、外見、衣類、カメラ、背景は別情報。見返りの首の回転を「視線」と一括削除しない。
2. **英文と3Dを同じID・revisionで結ぶ。** 画像だけ、英文だけが更新されて不一致にならないよう、素材の版とhashを記録する。
3. **3Dはポーズの資料として使う。** 素体の顔・体形・質感をキャラクターの本人性として指定しない。人物参照画像とポーズガイドは別の役割とする。
4. **元の生成例を保存する。** Krea/Qwen両画像を比較用に保持し、生成時の参照には初期状態で渡さない。元画像から外見や衣類が混入するのを避ける。
5. **文法を構造化する。** `she → he/they` の全置換ではなく、主格・目的格・所有格・再帰代名詞・動詞の活用をtemplate化する。
6. **現在の生成経路を使う。** 新しい生成エンジン、サービス管理、翻訳用LLMは増やさない。新しい素材読込口が必要な場合は既存経路との重複を先に確認する。
7. **用途別の欄で調整する。** 表情、ポーズ、アングル、レンズ、目線を分ける。読取元の情報と既存作品のアクション本文を保持し、利用者が各欄で調整した内容を優先する。混在する既存情報を分類する際も内容を黙って捨てない。
8. **検索は日本語タグと同義語から始める。** 採用30件を端末内で絞り込む。英文promptも検索対象にするが、検索用の日本語をpromptへ混ぜない。embeddingは初期実装に含めず、自然文での曖昧な検索が必要になった時点で検討する。
9. **一覧は猫のポーズ絵で選ぶ。** 利用者指定の猫イラスト30枚を固定pose IDへ対応づけ、短い名前とともに並べる。猫の絵は選択用の記号であり、頭・指・関節角の精密な資料にしない。元の承認済みPNGと、共通素体からの撮影画像を別に保持する。[表示画像の記録](2026_10_09_human_pose_cat_previews.md)を参照。
10. **日本語編集の差分を英文へ反映する。** 選択時の日本語・対応する基準英文・編集後の日本語を別々に持つ。LLMは変更のある意味単位だけを修正し、触っていない部分は元の英文を使う。
11. **全指示を確認してから英文化する。** 自動で付く人数や人物参照の指示も一覧に出す。確認後に日本語部分を英文化して生成へ進み、完成英文・元の一覧・適用差分を同じjobへ保存する。通常の流れで同じ内容の確認を二度要求しない。
12. **送り方を明示して切り替える。** `prompt` ではpose画像を送らず、`image` では確認した撮影画像を送り、矛盾する編集pose文を混ぜない。両方の入力状態を保持し、送信対象だけを切り替える。
13. **姿勢と撮影設定を分ける。** bone/root transformは共通素体に適用する。元画像に合わせた比較用カメラと、作品で使う撮影カメラは別に持つ。アングル・画角は撮影設定から決め、単一の静止カメラからパンや移動の軌跡を捏造しない。

## 保存先と共通契約

以下は現行素材の構造。研究資料と採用素材の出典・画像を区別し、存在しないKrea/Qwen画像を採用30件の必須fileにしない。

```text
.human_pose/
  catalog.json                     # 採用30件、template、素材revision、出典への参照
  sources/
    LICENSE
    index.json                      # 研究資料のrevision、元URL、取得日、hash
    study/pose/*.md                 # 出典の記述をそのまま保存
    study/common.md
    curated/index.json              # 採用30件の配布元・BVH・確認記録への参照
  models/
    human_base.blend                # 編集可能な正本
    human_base.glb                  # 表示・読込用
    human_base.metadata.json        # 元ファイルhash、rig仕様、修正内容
  poses/<pose_id>/
    pose.json                      # bone/root姿勢、接触、比較カメラ、確認記録
    pose.glb                       # 必要時だけ作る派生キャッシュ。正本・必須fileではない
    preview.png                    # 承認済みの元3D PNG。猫の表示画像とは別
    references/krea.webp            # 研究68件の比較資料（採用30件には要求しない）
    references/qwen.webp            # 同上
  review/
    index.html                     # 研究68件・旧6試作の比較入口
    <検証ごとのfolder>/             # 採用30件の登録・頂点照合・撮影結果等
```

素材ID、ファイル名、object、mesh、armature、material、action、表示名は汎用名にする。由来の監査には元ファイルのhashを使い、runtimeに元フォルダの絶対pathを持ち込まない。

人物ごとの選択は `Figure.human_pose` にID・catalog hash・基準日英・日本語編集値・`input_mode` を保存し、`scene` に素材hash・配置・撮影カメラ・寸法を保存済み。保存型の正本は `humanPoseTypes.ts`。現在の初期値は `prompt`。送り方の切替、関節の微調整、モーションの時点、背景内の設置点・基準・高さ補正・正面を保存する。生成ジョブ保存はP5の残項目。背景とカメラ型を共有し、将来の同一カメラ運用で別の正本を重複させない。表情情報はポーズの編集値と分ける。`Character.gender` は `female | male | neutral`。作品へ素体やPNGを埋め込まず、生成ジョブには送り方・確認一覧・適用差分・最終英文・撮影設定・実際の入力画像・素材情報をsnapshotとして残す計画。素材欠落時も選択を黙って解除しない。`prompt` を保存済みの文章と撮影説明だけで準備できる場合は、画像を必要とする操作と区別する。

猫の表示画像はGit管理する `src/assets/human-pose-cat/` と `humanPosePreviewArt.ts` にある。現在の撮影PNGはダイアログ内のプレビューのみで、PNGジョブ保存・Qwen送信は未接続。

`.human_pose/` はローカル素材として保持し、初期方針では大容量の `.blend`・画像等をGitへ自動追加しない。schema・読込コード・制作script・小さな合成fixtureはGit管理する。P1で既存ignoreとバックアップ経路を確認し、素材一式のmanifest・hash付き書出しを計画する。ローカルcommitだけでは素材のバックアップにならない。

## 段階共通の進め方

- 編集前に共有掲示板へ、その段階で実際に書くpathだけを登録する。各計画の「候補」は予約ではない。
- 素体の元データ、既存作品、他作業の未commit変更を保持する。開始時のHEADと差分を記録する。
- 節目で全差分と対象の検証結果を確認し、当該作業だけをローカルcheckpointへ保存する。push・公開はこの計画に含めない。
- 各段階の末尾に、実施日・変更path・検証結果・未検証・次の段階へ渡す契約を追記する。
- 自動テスト成功、Blenderでの見た目確認、ニャムルUI確認、実Qwen生成、利用者の確認は別々に記録する。

## 全体の完了条件

- 採用30件すべてに日英文、共通素体で再現できる姿勢、承認済みPNG、配布BVHの出典、revision、確認状態がある。利用者未確認の作業データと確定座標を区別する。
- 指定素体の手作業を保持し、汎用名の編集可能な素材として再利用できる。
- 女性／男性／中性の設定が保存・再読込でき、英文の代名詞と動詞が一致する。
- ニャムルで日本語キーワードを組み合わせて絞り込み、単純なポーズ絵から選び、モデルと英文と元画像を確認して既存の生成経路へ渡せる。
- 用途別の日本語欄で微修正し、自動指示を含む全promptの一覧確認後に差分反映・英訳・送信できる。既存の混在したアクション本文も失われない。
- `prompt` と `image` で送信するpose情報を切り替え、人物参照やカメラ由来の説明は共通に使える。切替で編集値が消えず、未送信の文章や画像を送信済みと表示しない。
- 配置・向き・カメラの調整と、ポーズの文章編集の作用範囲が明確。実装した範囲の接地・座面配置を確認し、細かな関節編集を完成扱いにしない。
- 少数の実生成でポーズ追従と人物らしさを確認し、全30件の素材検査とは区別して結果を報告する。
- 素材不在、非対応の生成モード、参照数超過、変更後の再生成に対し、理由と対処を表示する。
