作品カタログは描画の公開入口を経由せず、必要な座標関数を直接参照する。実行時の静的な相対import／re-exportを辿ると、分割前の循環1組は分割後に0組。フォントの権限確認は従来どおりページごとに行い、CLIP書き出し中は同じページの同じ書体データだけを再利用する。異なる文章2件で読み出しが1回になり、次のページでは読み直すことを確認した。

- 型検査、統合した画面関連355件、正本の座標・描画・保存・起動・CLIP・資料照合など162件、ほかに各保存点の対象テスト。件数は重なるため合計していない。
- 分割前後でAppの165個のフックの順序・引数、通常版・LAN版の起動画面と6タブの初期HTMLが一致。通常表示・旧ビューポート想定の両方で生成CSSがバイト単位で一致。
- HTTPの64経路の条件・処理とCLIヘルプを照合。LANの接続・再起動・HTTPSに関する5件、サービスの起動終了と所有権に関する23件が通過。
- 正本の実ブラウザーで通常版とLANモードをそれぞれ起動。合成作品を開く → タイトル編集 → Undo → Redo → 書き出し形式をCLIPに変更 → キャンセルを確認。両方でコンソール・ページ例外0件。通常版の作品読込サービスは模擬応答、LAN版のフォルダー選択は使い捨てブラウザープロファイルのフォルダーで検証。別端末からのLAN操作や実モデル推論は対象外。
- 検証用ブラウザーと一時サーバーは終了し、通常版・LANモードのポート解放を確認した。既存の作品への上書きなし。

分割で一部のPythonモジュールが、パッケージとしての読込とツール単独起動の片方で失敗していた。両方の入口を復旧し、他のテストの読込順に依存しないよう、新規プロセスで確認した。フキダシ形状を照合するテストは、定義の移動先を参照するよう更新した。

追加のブラウザー検証では51画面を開いた。LANゲートウェイ経由の漫画仕上げ、同時保存時の競合検出、画像取込中とUndo／Redo後の資料画像の保持は成功。未合格の操作は分割前の `f311a3b` と比較した。例えば、LANの画像付き保存試験は両版とも参照元画像が足りず停止し、描き文字設定試験は両版とも文字情報・Undo／Redoを通過したあと「5候補」の待機で停止した。これらの操作は合格件数に含めていない。

LANの検証は同一Mac上で実施した。別端末のフォルダー選択、CLIP STUDIO PAINTでの再編集、実モデルによる新規生成の画質は今回の検証範囲外。
