# 人物生成の単色背景・クロマキー透過仕様

作成日: 2026-10-30

**状態: 5候補の取得時透過・複数採用・未採用削除を実装。実モデルの画質は未評価。**

この文書は、人物を単色背景で5枚生成し、5枚すべてを取得時にコードで透過し、利用者が複数採用できる仕様を定める。現在の実装と確認範囲は[複数採用の記録](2026-11-02-multi-candidates.md)を参照する。本文の初期数値は試験開始値であり、画質・速度の実測結果ではない。

本画生成は[ComfyUIワークフロー接続仕様](COMFYUI_WORKFLOW_SPEC.md)に従う。ComfyUIで作ったAPI形式のワークフローを環境設定で登録・選択し、ローカルbridgeから標準APIで実行する。透過はニャムル側の後処理として残す。実装順序は[ワークフロー接続の実装計画](2026-10-30-comfyui-workflow-plan.md)にまとめる。

## 1. 目的と対象

- 白い服・肌・白目を残しながら、人物の外側と、腕・髪・脚の間に見える背景を抜く。
- 本画の生成と背景透過を分け、透過用に画像モデルを再実行しない。
- 取得時に各候補を1回透過し、透過済みの5枚から利用者の選択を待つ。
- 初回の適用対象は、既存の人物単品生成（`owner_key: figure-*`、`new` / `paint` / `sketch`）。参照画像の種類・順序・3D撮影条件・生成サイズを変更しない。
- ページ全体・コマ全体・背景生成の背景は抜かない。写植・描き文字の定型英文、本文保持、文章LLMを起動しない経路も今回の変更対象にしない。これらの5候補からの採用動作は維持する。

単色背景の目的は、背景と人物の色を分離しやすくすること。コードによる白抜きから緑抜きへの変更だけで、生成時間が大きく短縮すると約束しない。

## 2. 利用者の操作と状態

| 段階 | 表示・操作 | 実行する処理 |
|---|---|---|
| 生成準備 | 人物の指示・参照画像と背景色を確認 | ローカルの入力状態だけ更新。作品のUndo・保存を発生させない |
| 本画生成 | 実行中は入力操作を無効化 | 同じ指示・参照・背景色で、異なる5シードを順次生成 |
| 候補表示 | 透過済みの5枚を比較・複数選択し、選んだ候補を拡大表示 | 作品への挿入はまだ行わない |
| 作品へ追加 | 「選択したN枚を追加」 | 選択分を元フォルダーへ別レイヤーで一括追加し、生成通番を付ける |
| 未採用破棄 | 全選択分の追加成功後 | 未採用の緑背景PNG・透過PNGとComfyUIの対応する出力だけを削除 |

会話・音声からの生成も候補表示で停止し、自動で候補を選択・挿入しない。候補表示までに画像生成の利用を終了し、API接続仕様のメモリ解放・文章LLM復帰へ進む。ComfyUI Desktop自体を終了条件にしない。背景透過では文章LLM・画像モデルを起動しない。

閉じる操作や候補の選択だけでは作品を変更しない。あたり・既存レイヤー・手動ロックを保持し、追加は既存の1回のUndoで戻せる。候補と透過結果は同じジョブに保存し、生成履歴から再表示する。

## 3. 背景色

| 選択肢 | 指定色 | 用途 |
|---|---|---|
| 緑（既定） | `#00FF00` | 白黒漫画、および人物に緑を含まない絵 |
| 青 | `#0000FF` | 人物に緑が含まれ、青が含まれない絵 |
| マゼンタ | `#FF00FF` | 緑・青と区別しにくく、人物にマゼンタが含まれない絵 |

既存の生成ダイアログに、人物生成時だけ「背景色」の選択欄を設ける。初期値は緑。自動色判定、追加のVLM呼出し、色の安全性スコアは初回実装に含めない。人物に含まれる色は利用者が参照画像から判断する。同じ色を人物と背景が共有した場合に、コードだけで両者を必ず判別できるとは扱わない。

背景色はその生成ジョブの設定であり、作品全体の設定や恒久的な環境設定にはしない。実行開始後は変更不可。別色を試す場合は既存の「新しい生成を準備」から行う。同一バッチの5枚では同じ色を使う。

## 4. 本画生成の指示

既存の人物・表情・ポーズ・画風・参照画像の役割を維持し、背景指定の定型部分だけを単色背景へ切り替える。システムが付加する白背景指定やRGBA透明背景指定を、クロマキー用の背景指定と重ねない。利用者が入力した本文を一括置換したり、追加のLLMで書き直したりしない。

以下は、生成指示へ付加する**背景指定ブロックの全文案**。`{color_name}` と `{hex_color}` は上表の選択値を使う。

```text
Use a flat, uniform, solid {color_name} background ({hex_color}) for chroma key compositing. Fill every visible background area with this same color, including gaps between the arms, legs, and strands of hair. Do not add background gradients, texture, scenery, or cast shadows. Keep the character's original colors unchanged, without tinting the character or its outlines with the background color. Render an opaque image; transparency will be applied afterward.
```

緑の指定値は `color_name = bright green`、青は `pure blue`、マゼンタは `vivid magenta` とする。16進数を指定しても、モデルが全背景画素を完全にその値へ揃えるとは仮定しない。

実モデル試験前には、この追加ブロックだけでなく、既存指示と合体した実際の送信プロンプト全文・参照順・解像度・5シードを利用者へ提示する。今回の文書作成は実生成の開始を含まない。

## 5. 取得時の透過処理

既存の `scripts/qwen_background.py` を処理の所有箇所にする。Pillowと既存環境のNumPyで画素処理を行う設計とし、新しいモデル、常駐サービス、必須の外部ツールを追加しない。

### 色抜き

1. 取得した各候補PNGを1回読み込み、画像サイズを保ったままRGBAへ変換する。
2. 指定色と画素のRGB距離から背景への近さを計算する。外周からの連結性は条件にせず、画像全域を対象にする。これにより閉じた腕の隙間も、指定色なら除去対象になる。
3. 指定色に近い部分を透明、十分離れた部分を不透明、中間部分を半透明にする。
4. 候補に既存alphaがある場合は、計算したalphaと乗算して既存の透明部分を保持する。

RGB各成分を0〜1とし、キー色を `K`、画素色を `C` としたとき、初期実装はFFmpegの `colorkey` と同じ考え方の次式を使う。

```text
d = sqrt(((R - Kr)^2 + (G - Kg)^2 + (B - Kb)^2) / 3)
alpha_key = clamp((d - similarity) / blend, 0, 1)
alpha_out = alpha_in * alpha_key
```

| 内部パラメータ | 試験開始値 | 意味 |
|---|---|---|
| `similarity` | `0.08` | 完全に透明にする色距離の半径 |
| `blend` | `0.12` | 半透明から不透明へ移る範囲 |
| `despill` | 有効 | 輪郭に残ったキー色の補正 |

これらの値は未検証。単純なRGB距離だけでは、黒い線と緑が混じった境界を十分抜けない場合がある。第1回の実画像で残留する場合は、背景色成分の優勢度を使う境界alpha計算へ同じ関数内で調整する。方式を並列実行する自動比較・自動再生成は追加しない。

### 輪郭の色補正（despill）

- 処理対象は抜いた背景に接する狭い境界と半透明画素に限定する。初期の境界幅は出力画像の1pxとし、実画像で決める。
- 緑では赤・青に対して過剰な緑、青では赤・緑に対して過剰な青を抑える。マゼンタでは緑に対して過剰な赤・青の共通成分を抑える。
- 非境界の前景RGBは変更しない。全体の彩度低下、白黒化、ぼかし、線の描き直しは行わない。
- 白・黒・中間灰色の背景へ重ね、緑や白の縁、細線の欠落、輪郭の過度な収縮がないか目視で決める。色抜きと色補正の定数は独立に調整する。

## 6. 既存経路への組込み

背景指定はクロマキー対応のQwen人物ワークフローへ渡す最終プロンプトに含める。環境設定の登録・選択・入出力対応は共通の[API接続仕様](COMFYUI_WORKFLOW_SPEC.md)で管理する。汎用ワークフローやページ・背景用の定義へ、この人物用ブロックを無条件で追加しない。

| 所有箇所 | 実装内容 |
|---|---|
| `src/components/QwenGenerationDialog.tsx` | 人物用の背景色選択を既存draftへ追加。候補選択・結果プレビュー・挿入は既存処理を使う |
| `src/lib/qwenGeneration.ts` | 背景色を生成payloadへ渡す。5候補と会話の選択待ちを維持 |
| 既存の生成serviceとジョブ保存 | 選択したワークフロー・版・色抜き設定をジョブに確定し、取得時に同じ設定を読む |
| Qwen用プロンプト組立とComfyUI APIアダプター | 背景指定を最終プロンプトへ加え、登録定義の対応先へ渡す。本画の推論はComfyUIに任せる |
| `scripts/qwen_background.py` | 色距離・境界alpha・despillを一つの透過処理へまとめる |
| 既存の候補・worker・ブラウザ試験 | 白抜き前提の該当ケースを更新し、下記の受入条件を確認する |

設定の保存先は既存の `request.json` 内の `settings` とする。追加データの案は次のとおり。

```json
{
  "candidate_cutout": true,
  "transparency_mode": "chroma-key-v1",
  "chroma_key": {
    "color": "#00FF00",
    "similarity": 0.08,
    "blend": 0.12,
    "despill": true
  }
}
```

送信元は選択色を指定し、処理定数はbackendで確定する。透過時に現在開いている別の入力や変更後の既定値を参照しない。色抜き専用のHTTP endpoint、別のジョブ管理、設定専用sidecarは作らず、既存の `prepare` / `submit` / `reconcile` / `select` の責務を使う。ワークフロー登録の窓口は共通API接続の責務とする。

保存済みの候補・完成PNGは一括加工しない。既存の白背景ジョブをクロマキー設定と推測して扱わず、保存された `transparency_mode` で処理を選ぶ。新方式は新しく準備する人物ジョブから適用する。

## 7. 性能・失敗時の扱い

- 英訳と入力画像の準備は同一ジョブで1回行い、5シードを順次実行する。同一入力のグラフはComfyUIのキャッシュを利用できる形にする。conditioning・モデル・VAEの再利用回数とピークメモリは採用ワークフローで実測し、別プロセスの3工程と同じになるとは仮定しない。
- 各候補を取得時に1回だけ透過する。同じジョブの再表示・採用操作では保存済みの透過PNGを返し、再処理しない。
- 画質判定用モデル、透過率の合否判定、全候補の背景検査、保存PNGの反復照合は追加しない。
- 緑以外の景色や強い影が生成された場合、色抜きでは取り切れない。自動で閾値を広げて人物を削ったり、画像モデルへ再送したりせず、元候補と結果の見た目で利用者が判断する。
- デコードや保存に失敗した場合は既存のエラー表示を使い、候補と作品を保持する。候補の再生成はしない。
- 透過単独の初期目標は、現在のMac・768相当の採用画像で1秒以内、1024相当で2秒以内。PNG読込みから出力保存までを対象とし、実測前の目標として扱う。未達ならまず画素ループをNumPyへ集約する。追加GPUモデルで解決しない。

## 8. 受入条件

実装は[ワークフロー接続の実装計画](2026-10-30-comfyui-workflow-plan.md)の順で進め、API経由の本画生成が通った後に色抜きを接続する。実モデル試験では利用者指定の参照と送信プロンプトを確認し、取得した5候補を透過する。選択後に追加の生成バッチを実行しない。

### 確認する振る舞い

| 対象・見込み | 合格条件 | 確認範囲 |
|---|---|---|
| 単色背景と白い人物を区別できる | 合成画像の外側と閉じた隙間は透明、非境界の白・黒・色のRGBと不透明度を保持 | 実画素処理。モデルの指示追従は確認しない |
| 境界色を処理すれば色の縁が減る | 合成した半透明境界のalphaが段階的。非境界の前景RGBは不変。白・黒・灰上で残留色・細線欠落を確認 | 合成画像と採用した実生成1枚。全作品への一般化はしない |
| 背景色はジョブ単位で一意 | 緑・青・マゼンタの選択が保存設定と追加指示に一致し、採用時も同じ色を使う | 模擬通信と保存の往復。追加の色判定モデルなし |
| 採用するまで作品へ挿入しない | 5候補表示時に透過5回・挿入0回、候補2/4の追加で2レイヤー、再試行は重複追加・再透過0回 | 既存Dialogとservice。会話からも同じ選択待ちへ到達 |
| Qwen Turboが色抜き用の本画を作れる | 5枚の生成を完了し、利用者が選んだ1枚で白い服・顔・目・髪の細線を保持、外側と隙間の背景を除去。採用画像の画質を利用者が確認 | 実モデル確認。未実施の間は未判定 |

試験を追加する場合は、既存ケースを置き換え・拡張し、同じ条件を複数の試験基盤へ重複追加しない。結果には「合成・模擬」と「実生成」を分けて記録する。

## 9. 調査根拠と未確定事項

- [VNCCSの技術資料](https://github.com/AHEKOT/ComfyUI_VNCCS/wiki/Technical-Generator-Internals#pose-generation-internal-graph): Qwen 2511系の人物生成で単色背景を指示し、後段にクロマキーを用いる構成。現在使用するQwen Image 2.1 Turboでの品質保証を示す資料ではない。
- [FFmpeg `colorkey`](https://ffmpeg.org/ffmpeg-filters.html#colorkey): RGB距離の許容範囲と、半透明に移る境界幅を持つ色抜き。上記alpha計算の設計根拠。
- [Blender Keying](https://docs.blender.org/manual/id/5.1/compositing/types/keying/keying.html): クロマキーとdespill、境界調整を分ける設計。追加ツールの導入指示ではない。
- [Qwen Image 2.1公式モデルカード](https://huggingface.co/Qwen/Qwen-Image-2.1#transparent-image-generation-rgba): モデル自体には直接RGBAを生成する能力もある。本計画では利用者が指定した「本画の候補から選び、コードで透過する」構成を採用する。

Qwen Turboの背景色の均一さ、輪郭への色混入、顔・ポーズへの影響、適切な閾値、処理時間は実生成で未確認。クロマキーの出典だけを根拠に「白抜きより常に綺麗」「必ず1秒以内」とはしない。
