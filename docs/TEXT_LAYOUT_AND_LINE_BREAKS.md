# 吹き出しの文字配置と初期改行

## 適用範囲

- キャンバスの文字は、DOM Rangeで測った文字ブロックの外接矩形の中心を、しっぽを含まない吹き出しbboxの中心へ合わせる。各縦列は上揃えのまま。フォント・形・寸法・拡大率の変更、フォント読込完了時に再計測する。
- 自動改行は `createNewDocument` の新規ドラフトでのみ実行する。OCR→シナリオの正本照合→初期改行→新規作品確定の順。コマ内／ページ前景の吹き出しが対象。
- 変更するのは編集用 `bubble.text` への改行追加だけ。シナリオ原文、OCR控え、話者、強調フレーズ、対応状況、ト書き、画面内文字は変更しない。
- 手入力、候補の再選択、保存データの再読込、通常の保存・出力では再適用しない。現在開いている作品の本文にも遡及適用しない。
- 明示改行（CR/LF・Unicode改行）、全角空白、NBSP、タブがある本文は既存配置を優先してそのまま残す。`/` は一般の本文では改行記号と解釈しない。
- CSSによる表示上の折返し・縮小は従来どおりあり、本文への改行追加とは別。枠を小さくすると表示だけの折返しは起こり得る。

## 参考資料の再確認・再集計（2026-09-07）

ローカル `manga-babble-maker` の次の資料を読んだ。

- `docs/master-implementation-plan.md`
- `docs/implementation-open-questions.md`
- `manga_babble/text/breaks.py`、`manga_babble/text/profile.py`

明示した区切り、意味のまとまり、中央配置を重視する設計を参考にした。一方、既存コードの字数profileは実験的な既定値であり、資料にある文字数→列数表にも「14字要確認」と記載され、統計的根拠とは扱えない。

`samples/real/lines.json` と `samples/name/lines.json` を再集計すると、各8レコード、合計16だが本文は同じ8種類だった。明示区切りを持つ本文は5種類、区切り後は10区間で、文字数は昇順で **2, 2, 3, 3, 4, 4, 4, 5, 6, 7**、平均・中央値とも4字。これは1ページ分の小さな手作業サンプルで、見出し等も含む。漫画一般の最適字数や精度を推定できる規模ではない。重複を独立サンプルとして水増しせず、平均4字を製品の固定改行規則には採用していない。

再集計方法は、両JSONの `lines[].text` を完全一致で重複除去し、改行／全角空白／NBSP／`/` で区切った非空部分のUnicode文字数を数える。これは参照プロジェクトのマーカー規約に限定した集計であり、Nyamuruの本文変換規約ではない。制作原文や画像は本repositoryへ複製していない。

上記8種類は調査資料全体ではない。別フォルダ `Desktop/tools/テスト画像` にある `ahosuta`・`nagano` 各5枚、計10枚の完成原稿と対応する文字起こしも目視照合した。同じ10字でも2列・3列、13字でも2列・3列の例があり、[Issue #24](https://github.com/yukincom/manga-babble-maker/issues/24) の字数表は固定条件ではなく目安として扱う。演技による語中改行もあるが、意図を推測して自動再現はせず、原文の明示改行と読み込み後の手調整を優先する。文字起こしには注記・誤読・吹き出し境界の相違があり、全件集計や精度率の算出は行っていない。原稿画像・文字起こしは本repositoryへ取り込まない。

## 今回の初期改行

追加依存なしでブラウザ標準の `Intl.Segmenter` の日本語word・grapheme境界を使う。これは意味理解や完全な形態素解析ではないため、かなの活用途中、漢字と送り仮名、連続カタカナ、登録された人物名・別名、URL・英数字識別子、連続約物を保守的に保護する。基本的な行頭・行末禁則も適用する。

縦組の総文字数Nと列数Kから文字ブロックの縦横比を概ねN/K²と見積もり、吹き出しbboxの比率に近い列数を候補上限にする。句読点・助詞など（は、が、を、に、と、で、から、けど、ので等）の後を優先し、単なる等分より意味のまとまりを残す。候補上限以下の列数について、列長の偏りと区切り位置のコストの平均に、列数を減らすペナルティを加えて比較する。無理な列割りは避け、狭い枠で長い単語しか分けられない場合は1列のままにすることもある。形状内側の輪郭や字形別の実幅まで最適化したものではない。

列数上限12、最短列2文字、6書記素未満は改行なし、512 UTF-16コード単位を超える長文は対象外。これらは計算量・過分割を抑える実装上のヒューリスティックであり、漫画コーパスから学習した値ではない。bbox不明時の縦横比は1.6、異常値も同じ既定値を使う。Segmenter非対応環境は本文を変えずに表示へ進む。

禁則の考え方は [W3C 日本語組版処理の要件 §3.1.7–3.1.10](https://www.w3.org/TR/jlreq/) を参考にした。全規定の実装や編集者レベルの自然さを保証するものではない。特に全ひらがな、未知の固有名詞、語りの間・演技による区切りは手調整が必要になり得る。

## ライセンスと今後の統計

参照したローカル `manga-babble-maker` には明示的なLICENSEが見つからなかったため、「導入可能なOSS」とは扱わず、実装やサンプルを転載せず設計を参考に独立実装した。今回のnpm/Python依存追加・モデル取得・外部AI送信はない。

この機能の目的は、OCRで失われた改行を新規読み込み時に自然な初期配置へ補うことであり、プロ原稿の完全再現ではない。原文シナリオに改行がある場合は、連結されたOCRとの照合後も原文の改行を保持する。大規模統計や精度率は未取得だが、字数・縦横比・言語境界のヒューリスティックとして利用する。

## 検証

自動テストで本文保存性・明示改行・URL・書記素・名前・かな活用・禁則・初期適用場所・保存再読込を確認。配置ロジックは0.5／1／3.05倍の座標変換、フォント変更時の再計測と両ownerの共有を検証する。実ブラウザでは制作データを変更せず、別の一時ページで形状7種×寸法3種×本文4種の84条件を表示し、文字矩形が非空、中心差0.5px以内、列の上端差0.5px以内、はみ出し1px以内を確認した。一時ページは検証後に削除する。
