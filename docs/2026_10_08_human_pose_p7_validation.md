# P7: 全体検証・引き渡し

作成日: 2026-10-08 / 整合更新: 2026-10-10 / 状態: 全体検証は未着手。P5/P6の変更範囲の検証記録は再利用する

[全体計画](2026_10_08_human_pose_plan.md) / 前提: 現行P1/P2/P4/P5/P6の必須条件を満たすこと。P3は旧試作の履歴保持

## 目的

出典、共通素体と大まかな姿勢データ、性別属性、配置・接地・撮影設定、文章／撮影画像の2モードが一つの利用手順としてつながることを確認する。初期アプリの細かなポーズ調整は文章編集とし、関節編集や将来の人物フォルダー一括生成を完了条件へ混ぜない。採用30件の素材検査と代表素材での実生成を区別し、比較・修正・復元できる状態で引き渡す。研究68件/136画像と旧6試作は履歴・参考として保持し、追加制作を要求しない。

## 検証の区分

| 3D素材 | 採用30件 | 共通base＋pose.jsonからの再構築、大まかな姿勢・接触・近似の目視記録。17/23の手直し保持 |

| 日本語編集・差分英文化 | 代表の追加・削除・左右変更・無変更 | 基準日英と編集値、未変更segmentの保持、無効patchの拒否 |

## 1. 静的・自動検証

- catalog、画像、共通GLB、pose.jsonの全inventoryを照合し、欠落・重複・別ID混入・破損・hash不一致を検査する。pose別GLBは必須とせず、任意キャッシュがある場合は正本から再生成できることを確認する。
- schema、座標系、base hash、rig signatureが揃い、tokenや内部enumがUIへ露出していないことを確認する。
- optional fieldなしの既存作品と、全属性・pose選択付き作品を読み書きする。人物削除・再割当て、複製、Undo/Redo、シリーズ人物mergeも検証する。
- ポーズなしの生成requestとpaint経路が保持されていることを確認する。文章モードはpose画像を含まず、画像モードは確認済みのpose画像を含み、保存だけの編集pose文を翻訳/結合しないことを検証する。各role・対象・番号・hashと実際のencoder入力が一致することを確認する。
- 準備後に送り方・人物属性・配置・cameraを変えた場合、古いsnapshotを誤ってsubmitしないことを確認する。
- 選択時の基準日本語・基準英文・編集日本語が保存され、素材更新や再読込で差分の基準を失わない。未編集なら元英文を使い、削除条件を復活させない。
- 人数、人物参照、外見保持、mode、透過等を含む確認一覧と最終model promptのblockを照合する。LLMが変更対象外の英文を変えようとしても、その変更を採用しない。
- cameraの数値から作る説明を決定的に検査する。方位・俯仰角・左右・FOVの境界、描写範囲、camera変更後の再撮影、手入力override、未対応魚眼、目線未入力を含める。
- 計画分の完了時にrepository全テスト・型check・buildを行う。既存 `npm run verify` とpackage scriptsの対象を確認し、不足する全体テストを補う。各段階の変更範囲の検証記録も引き継ぎ、文書だけの変更や同一状態で重複して重いtestを回さない。

## 2. Blender・3Dの確認

- 元ファイルのhashが保持され、派生baseを開き直して可動・driver・書出しを確認できる。
- 採用30件をcamera別に見て、大まかな姿勢の左右、重心、接触、関節の破綻、支持物、床への埋まりと近似範囲を確認する。確認済みの座標を共通素体へ再適用し、確定時と同じ姿勢になることを確認する。P6の全頂点照合は再現性の根拠として使い、生成適合や接地の目視確認に置き換えない。
- 初期範囲の平らな設置面と登録座面で配置補助を確認する。床未検出、接地OFF、支持脚変更、座面高さの違いを含め、関節を曲げて足を届かせたと偽らない。
- 現行30件は支持物・接触点が未登録。P5で登録・接続した対象と未対応対象を区別し、存在しない床/座面への自動配置を完了扱いにしない。鏡反転の支持物/接触処理は非空fixtureでも確認する。
- 全件の目視結果を記録する。検査scriptによる頂点・file検査だけで、自然な人体姿勢と判定しない。
- 派生file名と内部labelを調べ、固有キャラクター名が残っていない。外部実験folderや `.codex` にruntime依存がない。

## 3. ニャムルの実UI

1. 既存の検証用作品で人物を選び、性別欄を3通り変更し、保存・再読込で保持されることを確認する。
2. コマ内とページ前景で用途別の欄を確認する。「表情情報」からポーズ検索・日本語本文が続き、選択・微修正・仮選択・取消・解除がその人物にだけ作用することを確認する。既存の混在したアクション情報も失われていないことを確認する。
3. 承認済み元PNG、英文、3Dを見比べ、cameraの閲覧操作と確定操作の違いを確認する。猫イラストは選択用と分かり、研究資料の元2画像を採用30件へ要求しない。
4. 送り方を選び、生成previewで実際に送る文章/画像、人物割当て、出力画角、すべての指示を確認する。「確認して生成」後に必要な差分反映・英訳へ進むこと、通常の流れで二度の確認を求めないこと、実際の最終英文が保存されて閲覧できることを確認する。
5. 素材の欠落・revision差、参照画像の上限、未対応paint、準備後の変更を検証用fixtureで起こし、対処が分かることを確認する。利用者の本物の素材を削除して試さない。
6. キーボード、focus、Escape、画面幅が狭い場合の選択操作を確認する。
7. 「座る／座り／sitting」「座る 足を組む」「椅子 足を組む」「あぐら」、未知の語、空欄を試す。実catalogに該当素材がなければ0件を正解とし、期待するID集合と照合する。
8. 猫イラストで大まかな姿勢を判別でき、正しいpose IDの3Dを開くことを確認する。猫の顔方向・指・角度の精密一致は要求しない。入力・hover・検索条件変更だけで確定値が変わらず、取消で元の選択を保持する。
9. pose本文の微修正後も3Dが自動変更されたように表示されないことを検査する。文章→画像→文章の切替で編集文が保持され、画像モードでその文が送信対象外と分かることを確認する。撮影previewの確認は全指示の確認に含め、別の必須確認を重ねない。
10. 3Dの配置・向き・cameraを調整し、アングル・レンズ説明が実際の設定に対応することを確認する。目線未入力や静止cameraから、視線や移動軌跡を勝手に作らない。
11. 体勢の基準/鏡反転を選び、同じ選択の繰り返しでtoggleしないこと、顔方向・camera・配置と本文を保つこと、保存・再読込・Undo/Redo・取消と撮影preview失効を確認する。基準姿勢の左右定義がない素材を、反転値だけで左向き/右向きと断定しない。

利用者の作品を検証で書き換えない。必要なら既存の検証作品またはcopyを使い、変更した値と復元結果を記録する。

## 4. 実生成と結果の読み方

- P5の同条件比較をまず確認する。コード・guide・promptが変わっていなければ同じ生成を無条件に繰り返さない。
- 修正が品質へ影響した場合、該当する代表poseだけを再生成する。採用30件すべての実生成や研究136画像の再生成は、初期の引き渡し条件にしない。
- 記録項目は、送り方・pose ID・asset revision・人物・解決性別・実際に送るprompt・配置/camera設定・画像モードのguide hash・人物参照hash・model設定・seed・結果・所見。
- 「ポーズが合う」と「元画像に似る」を区別する。服装・顔・体形を元画像へ寄せることは評価目標にしない。
- 単独人物の成功だけで複数人物の割当てを保証しない。複数人物を対応範囲に含めるなら、異なるposeを指定する代表例を少数確認する。
- 少数の成功を全30件の生成品質保証に拡張しない。素材の全件検査と実生成の代表検査を別々に報告する。

## 5. 保存・復元・利用手順

- `.human_pose/` 一式のmanifestとhashを作る。既存の書出し／バックアップ機能を優先し、重複する同期サービスを追加しない。
- Git管理するcode/schema/scriptと、ローカルに保存する大容量素材を一覧化する。commitに含まれない素材の所在を明記する。
- 一時的な復元先へ書き出した素材を読み、catalog・GLB・参照画像を表示できることを確認する。既存の正本へ上書きする復元testは行わない。
- 日付付きdocsへ、素材選択、性別設定、配置・接地・camera、文章でのpose調整、送り方、比較・生成、catalog再作成、欠落時の対処をまとめる。READMEには必要なら入口だけを追加する。
- 新しい利用手順docの正確なpathを決めてclaimへ登録してから作成する。実装前の手順を動作確認済みとして書かない。

## 引き渡し条件

現行P1/P2/P4/P5/P6の必須条件を満たし、P3の旧試作を履歴として保持する。旧6件の採用・全68件の3D制作は要求しない。未解決の不具合は対象と影響が明記されていること。最終報告には次を含める。

- codeのlocal checkpoint、素材保存先、比較画面の入口。
- 採用30件の登録・検査結果、17/23の手直しと原本の保持、共通素体＋姿勢データによる再現、汎用名称の確認。研究68件・旧6試作の保存先も記載する。
- 性別欄と英文の保存・往復・文法の検証結果。
- ニャムルUI、配置・camera説明、2モードの実入力と少数の実Qwen出力の確認結果。
- 未対応mode、既知の近似、未実施の生成条件、利用者未確認の項目。

最終commit前にstatus、全unstaged diff、staged diffを確認し、当該作業だけを含める。共有掲示板へcommitと検証・残存変更を記録してclaimを解放する。push・外部公開は含めない。
