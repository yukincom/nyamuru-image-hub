# ネームの人物ラフからのQwen生成と背景透過

## 使い方

1. キャンバスで登場人物のあたりを右クリックし、**生成**を選ぶ。**参照画像**で、その人物フォルダ内のラフのレイヤーを選ぶ。参照は自動選択しない。
2. **この人物の登録資料を読み込む**、または**設定画を追加**でキャラクターの資料を指定する。設定画以外の画像はフォルダ内のレイヤーから選ぶ。修正箇所を指定する画像・マスクは、任意の**ピンポイント修正用**欄で1枚選ぶ。
3. **生成指示**で動作・表情・視線を確認する。人物のアクションは初期値に含まれる。コマのト書きは、既存の**人物へ注入**で人物のアクションへ反映してから生成する。
4. **Qwenで実行**を押す。完成した透過PNGを確認し、**このあたりに差し込む**、または**生成画像を保存**を選ぶ。

ラフは1人ずつ切り出した画像を使う。人物資料の三面図は1枚の資料として渡す。ラフのポーズ・構図・見切れと、人物資料の外見・画風を別の役割として扱う。生成結果の市松模様は透明部分の表示で、PNGには焼き込まれない。レイヤー選択と局所修正の仕様・検証状態は[2026-10-13の記録](2026_10_13_qwen_layer_inputs.md)を参照。

## 実装

- 既存の人物crop保存、Qwenジョブ、英訳、生成履歴、画像差し込みを使用する。APIや翻訳サーバーを別に新設しない。
- 修正用画像を使わず、ネーム由来のあたりレイヤーを参照に選んだ場合は`sketch`モード。実験で確認したQwen-Image-2.1 Turbo、8 steps、768相当、CFG 1、Euler、固定sigmas、seed 260921を使用する。選択レイヤーはフォルダの描画範囲で書き出し、その比率を出力へ使う。
- まず白背景で人物画を生成し、次にその完成画だけを入力して透明度を生成する。最終PNGは**最初の完成画のRGB + 2回目のalpha**。2回目のRGBを採用しないため、透過工程で描き直された色や線は混入しない。
- 背景の透過は[Qwen公式のRGBA指示](https://github.com/QwenLM/Qwen-Image-2.1)を使用する。白い服や肌も不透明にする指示を含む。寸法不一致、alphaなし、透明部分または不透明部分が1%未満の結果は成功として扱わず、原本をジョブ内に保持する。
- CPU VAEを使い、導入済み環境のMPSで生じた5D padding問題を回避する。各工程は別プロセスで終了し、既存の画像生成leaseとQwen排他ロックを引き継ぐ。
- 全生成モードで、開始時の空きメモリ21 GiB、実行中6 GiB、swap増加1 GiBを基準に中止する。MPS割当の上限設定は16 GiB。driverの報告値には別の領域も含まれるため16 GiB以下を保証する指標ではない。
- 通常生成・ペイント参照生成もTurbo・8 stepsを使用し、出力は1024相当。2026-10-13の切り替えと過去ジョブの扱いは[全生成のTurbo統一](2026_10_13_qwen_all_turbo.md)を参照。検証中に保存した1工程RGBAラフジョブも読み出せる。

人体3Dポーズを設定した人物に対する既存の未対応案内は継続する。この機能は2Dネームラフ用である。

## 検証記録

正本: `<repository-root>`。既存labのモデル・実行環境を使用し、モデル追加や依存パッケージ追加は行っていない。

実モデル検証は、利用者が指定した小雪の資料と走るラフを使い、アプリが組み立てた日本語指示を既存のローカル翻訳処理へ渡した。追加演技は「目線はつま先に向ける。険しい表情、冷や汗」。生成ジョブは `3574c70f-40ca-46ba-9b6b-faa6ede628ad`。

| 項目 | 結果 |
|---|---|
| 出力 | RGBA PNG、736 × 800 |
| 生成から透過まで | 178.1秒（英訳の準備時間を除く） |
| alpha | 最小0、最大255。ほぼ透明77.36%、ほぼ不透明21.88% |
| 透過前後のRGB | 全画素で一致 |
| PNG SHA-256 | `0970b6d96d5b653a245746a7591a4a5f7786cd8d16c195b1ccb6f83023cb1431` |
| 最小空きメモリ | 9.97 GiB |
| 最大MPS割当 / driver報告 | 11.55 / 16.45 GiB |
| 観測swap使用量の変動幅 | 8 MiB |

背景・腕の間の透過、白い服と肌の保持、表情と汗を市松背景で目視した。画面左側の袖は資料の黒が一部反映されず、手の線にも乱れが残る。透過工程は完成画のRGBを保持するが、人物を描き起こす工程の画力・資料一致・視線の正確さを保証するものではない。輪郭の透明度も生成結果なので採用前に確認する。

同日の1工程RGBA生成では服の描き込みが弱くなったため、上記の2工程を採用した。過去の試行を最終結果として扱わない。

実画像・計測・ログは `.local-generation/qwen-storyboard-verification/` と上記のQwenジョブ内に保存。利用者の原稿・資料フォルダには検証画像を追加していない。
