# ハンズフリーの軽量対話（2026-10-20）

エージェントの入力欄に、用途の異なる2つのマイクボタンを置く。

- **時計付きマイク — 軽量対話**：一度オンにすると、発話が途切れて無音が1秒続いたところで文字起こしを自動送信し、操作を実行する。送信ボタンは不要。処理が終わると自動で次の発話を待つ。もう一度押すとオフになる。
- **通常のマイク — 手動入力**：考えながら間を置いて話せる。録音中は「じっくり入力中.........」と点を動かし、四角い停止ボタンで終了する。文字起こしを入力欄で確認・修正してから送信する。

軽量対話をオンにしても、入力欄に残した手動の下書きは自動送信に混ぜない。画面にはオン・オフと自動送信の状態を表示する。文字起こし・実行中は新しい発話を取り込まず、完了してから聞き取りを再開する。処理中でも軽量対話をオフにできる。

「環境設定 → AI → エージェント」で、無音を待つ時間を0.5・1・1.5・2・3秒から選ぶ。続けて話すと、最後に声を検出した時点から数え直す。設定は端末に保存し、次に軽量対話をオンにしたときから反映する。マイクのオン状態は保存せず、画面を開いたときは両方オフ。

## 実行と停止

既存の `createEditorDictation` と、文字の送信にも使用する `runAgentConversation` / `runVoiceCommand` を使用する。軽量対話の発話だけを自動送信し、分類・引数・対象・原稿の変更検証は既存処理を共有する。新しいHTTP入口やモデル呼び出し経路、プロンプトは追加しない。

軽量対話では同じマイク接続を保持し、発話の録音・文字起こし・実行を順に処理する。無音だけの場合はオンのまま待つ。短すぎる音や空の認識結果は送信せず、次の発話を待つ。1区間は最大30秒。録音・認識エラー時は停止し、画面に理由を表示する。

軽量対話をオフにするか会話を閉じると、録音と未処理の音声を破棄し、遅れて届いた認識・分類結果から新たな操作を始めない。既に開始した保存などは取り消せない。手動入力の停止は、最後の音声を文字起こしして下書きに残す。

## 検証

- 録音・画面状態・設定の対象テスト22件が成功。連続2発話の自動送信、実行完了まで録音を待つ処理、無音待受、文字起こし中・分類中・最終録音イベント前の取消し、手動の下書き保持を確認した。
- `npm run verify` が成功。型検査はエラー・警告0件、Nodeは1015件中1012件成功・3件スキップ。Pythonの428・18・45件の各テスト群と通常版・単体HTML版のビルドも成功（環境依存のスキップあり）。
- ブラウザーで軽量対話を一度オンにし、送信ボタンやマイクを押し直さず、2回の発話が各1回実行され、次の待受に戻ることを確認した。3回目の分類を待つ間にオフにすると、結果が返っても実行回数は2回のままだった。
- 通常のマイクでは、無音中も「じっくり入力中.........」と録音が続き、文字起こしは下書きに入った。停止だけでは実行せず、送信ボタンを押したときだけ実行された。

画面確認は、実際のブラウザー録音処理へ合成信号を入力し、文字起こし・分類・保存応答を検証用に置き換えて行った。実マイクでの認識精度や周囲の音を含む発話区切りは未検証。確認画面と結果は `output/voice-handsfree-2026-10-20/` の `twice.jpg`、`twice.txt`、`cancelled.txt`、`manual.txt`、`manual-sent.txt`、`focused.log`、`verify.log` に保存した。
