# CLIP STUDIO用の書き出し

画像書出の形式に「CLIP STUDIO（.clip＋元データ）」を追加した。保存先選択・ページ範囲・進行表示は既存の書き出し画面を使い、1ページでもCLIP本体と元データを同じZIPに保存する。作品の保存・Undo履歴は変更しない。PSDは統合画像のままで、編集用の出力はCLIP形式を選ぶ。

## 保持する内容

| 内容 | CLIP内の扱い |
|---|---|
| 基本文字 | 本文・位置・pt・縦横書き・行間・揃え・太字／斜体を持つテキストレイヤー |
| フォント | 実際に描画できるファミリーを選ぶ。Local Fontsが既に許可済みならface名・PostScript名まで対応させる。実太字／斜体faceへ擬似書式を重ねない |
| 画像・描画 | 個別ラスターレイヤー。元画素のalphaとレイヤーopacityを別々に保持 |
| 有効なマスク | 画像と別のレイヤーマスク。コマ境界・配置のcropもマスクとして渡す |
| 線 | 単純な線は編集可能なベクターレイヤー。曲線は出力画素で0.2pxを目安に細分化 |
| フォルダー | 階層・表示・ロック・通過／通常合成。原稿全体の描画順を保つためコマは工程ごとのフォルダーに分かれる |
| 元データ | SVG・画像原本・文字書式・描画JSON・レイヤー対応表をZIP内の各ページの `-sources/` に保存 |

塗り・特殊ブラシ・部分書式・下線・取り消し線は、表示画像と非表示の編集用文字／線へ分かれる場合がある。フキダシの形・しっぽ・結合は表示画像と元SVGを保存する。無効化済みの描画マスクや元の曲線ハンドルなど、CLIPで直接再現しない編集情報も元JSONに残す。変換上の注意は同梱する「お読みください.txt」と `layers.json` に記録する。

フォント自体は同梱しない。開く端末に同じ書体がない場合やファミリー名だけで対応させた場合は、クリスタ側で置き換わることがある。ブラウザーとクリスタの文字組みが全書体で一致することは未検証。

## コピー元と接続

[Name StudioのMIT版](https://github.com/nanikasheila/name-studio/tree/9ff110d7b8ee9a6e1113769a8c64eb0353ab9801)と[csp-formatの固定版](https://github.com/nanikasheila/csp-format/tree/aaa4e3a0cf6080d780a652a40d236d28e5df59a9)を同梱した。元ファイルは `scripts/clip-export/UPSTREAM.json` のSHA-256と照合する。差分は5宣言の `pub(crate)` → `pub` だけで、元の関数名・処理本体は保持している。[詳細とライセンス](../scripts/clip-export/README.md)。

にゃむるのレイヤーを読み出す処理は `src/lib/clipExport.ts`、CLIPの生成への接続は `scripts/clip-export/src/main.rs`。ひな形の600dpi換算値を出力ページのdpiへ合わせ、書体・文字書式・線色・表示状態を接続側で指定する。

ローカルbridgeの `/api/export/clip` が固定の実行ファイルへJSONを渡す。保存先の選択とZIPの作成は編集ブラウザーで行う。画像・本文を外部サービスへ送信しない。LANも既存のOrigin検査とbridge起動／終了経路を使う。

初回の変換器準備は、Rust 1.88以降とCコンパイラーがある環境で `npm run setup:clip`。生成物は正本内の `.local-clip-export/bin/` に置く。通常の書き出し時にRustは不要。このMacでは準備済み。Webだけの配信環境ではローカルbridgeが必要。

## 確認した範囲

- Node対象試験19件成功。コピーの同一性、文字・書体対応、折り返す曲線、長い作品名でもページ名と元データ名が重複しないこと、PNG/PSDの既存出力と保存処理を確認。
- Rust対象試験5件成功。実CLIPを再読込して本文・サイズ・書体・順序・線色・半透明画素・mask濃淡・opacity・ロックを確認し、構造検査にも合格。擬似太字／斜体と実faceの重複を防ぐ属性も確認。
- Python対象試験4件成功。実変換器のHTTP handler経由の往復と、失敗・時間切れ・再試行の処理を確認。
- LAN対象試験5件成功。変換要求の転送と異なるOriginの拒否。転送先は模擬で、別PCからの実接続は未検証。
- ブラウザーでレイヤー変換29項目、実Appの保存14項目成功。合成原稿から実変換器を呼び、実OPFSへ書き込み、単ページ／複数ページ、元データ同梱、失敗後の再試行、作品・Undo不変を確認。OSの保存先pickerとbridge起動管理だけは模擬。
- 変更対象のTypeScript型検査成功。
- このMacのCLIP STUDIO PAINT EX 1.9.11でCLIPを開き、本文を書き換えて保存。保存後の実ファイルにも変更した日本語本文・ヒラギノ角ゴシック W3／HiraginoSans-W3・24ptが残った。150dpiの24ptは約50pxの実表示になった。
- 実クリスタで濃淡0／128／255のマスクを確認し、無効化すると隠れていた部分が戻り、元画像の濃さに戻った。マスクへのブラシ描き直し、ベクター線の実手動編集、全書体・全作品・別バージョンでの互換性は未検証。

クリスタ1.9.11では、初回の文字編集時にバージョンの異なる文字を置き換える確認が出る。検証原稿で承認すると編集できた。実作品での見た目確認は利用者のチェックを待つ。

全体ビルド・全件テストはrepositoryの指示どおり利用者のチェック後に行う。変換器の個別ビルドと上記の対象検証は実施済み。検証用サーバーは停止し4341の解放を確認、作業前から稼働していた4321は維持。push・公開は行っていない。
