# ニャムル v0.3 学習・評価手順（2026-10-18）

## 目的と入力

音声認識後の単独発話を、既存の19分類へ振り分ける分類器をColabで再学習する。モデルは発話本文textのみを見る。slots、注釈、出典、元のMASSIVEラベル、画面状態、会話履歴は入力しない。モデル・19ラベルID・学習条件はv0.2から変えず、データの追加と新しい評価を分ける。実際の音声認識、引数解決、アプリの操作実行はこの実験に含まない。

## データの役割

元316件とv0.2追加608件の計924件は、原文・注釈・ID・旧splitを保持する。旧train647件に、否定・延期、Undo/Redo、複数操作の追加288件と、選定したMASSIVE原文・派生例を加える。追加288件は旧testの誤分類を見て作成したため、全件train専用。旧dev138件と旧test139件は学習・条件選択に入れず、legacy_dev/legacy_testという回帰確認用の別poolへ置く。

新dev/testの漫画編集例は、ラベル契約だけを渡した別の作成担当が初稿を作り、モデル予測を見る前に既存例との同文・近接をレビューした。対象名、数値、引用本文、語尾だけを替えた明確な文型は除外する。補充例も同じ基準でレビューする。文字列類似度は候補抽出に使い、意味の独立性を保証する値とは扱わない。除外候補はtrainへ転用しない。

近接レビュー後は各分類の件数を均等に揃えず、dev/testとも各分類4件以上を確保した。これは近接例を減らす手動レビューであり、言語的な独立性の証明ではない。分類別supportとmacro F1を正解率に併記し、少数例の率を過大解釈しない。

MASSIVEの原文は公式train/dev/testを保ち、近い元発話群も同じpoolへ置く。派生合成例はtrainのみ。原文の質問・操作依頼を再注釈する際は、元の60 intentをそのまま19分類へ一括変換しない。原文と大きく書き換えた合成例は別のsource値で記録する。

最終件数・各分類のsupportはdata-report.json、全採用行はsplit-review.md、採用/除外と近接の判断はcuration配下に記録する。新dev/testは合成例中心であり、実利用者の未見音声として扱わない。公開資料がベースモデルの事前学習に含まれていたかは未検証。

## 学習前の固定

corpus.jsonは採用したJSONLだけを列挙する。全行を元JSONLのバイト列でdataへ配置し、SHA256、件数、19分類、ID、正規化同文、source partition、train-only制約、旧例の保存、family分離を検査する。出典確認用に同梱したMASSIVE全16,521件や除外候補を学習データへ読み込むことはない。

旧例と追加trainのfamilyが重なるのは、明示的に退役したlegacy poolとの間だけ許す。新dev/testはtrainにもlegacyにもfamilyが跨らないことを検査する。新devと新testのfamilyも分離する。公開元IDと元本文の正規化値が異なるpoolで再利用されないことも検査する。

prepare_v03.pyは新規poolを一時フォルダで完成・検証してから公開する。既存の固定dataや学習結果は上書きしない。tokenization-check.jsonはトークン数の確認であり、モデルの推論・学習結果ではない。最大128tokenを超える入力は切り詰めず、エラーで停止する。

## 条件選択と95%目標

sbintuitions/modernbert-ja-30m、revision 8cb03f54cb9e30e72459e5f1cedc6d89c7d8dcb5から全パラメータを学習する。3 seed（42/43/44）×2学習率（2e-5/5e-5）、10epoch、batch16、float32、SDPA、TF32無効。旧学習済みモデルの重みを初期値にしない。

1. 各試行の最良epochは、新devの19分類macro F1を優先し、同値なら低いloss、早いepoch、早い試行順で選ぶ。
2. 各学習率の最良dev成績を3 seedで平均し、共通の学習率を選ぶ。同値の順序は上記に従う。
3. 共通学習率で選ばれた3モデルのうち、新devだけで主評価モデルを1つ決め、selection.jsonへ保存する。
4. 条件・主評価seedが確定した後、初めて新testを予測する。3モデルすべてを残すが、test最高のseedへ採用候補をすり替えない。
5. 主評価モデルの新testで観測した正解率が95%以上かを報告する。macro F1、全19分類のsupport/precision/recall/F1、非命令→操作、Undo→Redo、Redo→Undo、複数操作→単一操作の件数と分母も併記する。

この95%は今回の固定text評価内の目標である。小規模な合成例中心の評価で95%に達しても、実ユーザー音声・ASR・現場の95%を示すとは判断しない。モデルの自動採用は行わない。

## 成果物の検証

全5splitについて、各行の本文・正解・19確率・argmax・familyを保存する。入力ハッシュ、各epochのdev履歴、選択の再計算、保存重みの形状・dtype・ハッシュ、再読込dev成績、全予測のメトリクス再集計をverify_results.pyで検査する。旧v0.2の固定予測と同じID・本文・正解のlegacy精度を比較し、独立評価と混ぜずに表示する。

この準備段階で実行するのは、データ検証・単体検査・トークン化・ノートブック構文/ZIP整合性の確認。CUDA学習と学習済みモデルの推論は、ユーザーがColabで実行した後の別の証拠となる。
