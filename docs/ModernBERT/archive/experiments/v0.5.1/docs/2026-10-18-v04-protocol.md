# ニャムル v0.4：単一操作と複数操作の対照学習

## 変更の目的

v0.3の主評価モデルは新testで117/132件正解（88.64%）。15誤り中7件が単一操作などから`compound_request`への誤判定だった。選択された他の2 seedは104/132件正解で、複数操作の見逃しもあった。この結果だけでモデル容量や特定データソースを原因と断定しない。

v0.4では既存の学習経路・モデル・学習条件を保ち、単一操作108件、複数操作72件、境界36件からなる216件をtrainへ追加する。理由・過去の報告・将来の予定・同じ操作の言い直し・対象や値の複数性を、現在確定している独立操作の数から区別する。設定の条件分岐が同じ最終値へ収束する例、否定や撤回の範囲、引用中の命令と実行依頼の違いも含む。例のラベルは既存19分類の契約に従う。

## データの作成と分割

追加trainはv0.3のtrain/devとラベル契約を参照して作成した。旧testと予測は作成担当に渡していない。旧testは親による誤り分析ですでに確認しているため、v0.4では独立した受入評価として扱わない。旧testに由来する失敗類型を新例に反映しても、元の評価行をtrainへ移動したり、元goldを書き換えたりはしない。

新devと新testは、それぞれ別の担当がラベル契約だけを読んで作成した。作成時に旧データ、追加train、他方の新評価、モデルの予測は参照していない。親は全候補の意味とslotsを読み、別担当が初稿の既存例との近さを確認した。正規化完全一致、数値・名前・丁寧語だけが違う例、同じ指示へ理由を付けただけの構文を除外する。操作名や一般的な日本語構文を共有すること自体は除外理由にしない。

字面の近さは全比較対象とのSequenceMatcherで確認するが、閾値だけで独立性を判定しない。採用・除外の理由と近い相手を記録し、類似した新評価をtrainへ転用しない。作成者が別であることやfamily名が異なることだけを独立性の証拠にはしない。新評価候補のラベル確認に分類器の推論は利用していない。

同じ対照群・言い換え群は一つのfamilyへ結合する。既存familyと追加trainの関係を残し、新dev/testを含むfamilyのsplit横断を禁止する。旧評価のfamilyがtrainと関係する場合はその事実を残し、診断用途に限定する。独立性はこの作成・重複除外手順に関するものであり、あらゆる言語的類似がないことや実利用分布との一致を保証しない。

候補568件から採用した新devは68件、新testは73件。除外427件は学習にも使わない。全19分類を含むが、分類別件数はdevが2〜8件、testが2〜6件と少なく、不均衡でもある。ラベル別精度やseed選択はこの小標本の影響を受ける。明示的な念押し・反復依頼の系列はtest側だけに残し、同系列のdev候補は除外した。

## 7つの評価先

| split | 用途 |
| --- | --- |
| train | 旧1080件と追加216件。学習と学習内診断 |
| dev | 新規作成。epoch、共通学習率、主評価seedの選択 |
| test | 新規作成。選択終了後の主評価 |
| legacy_v03_dev | v0.3のdev 88件。同じ例での回帰確認 |
| legacy_v03_test | v0.3のtest 132件。同じ例での回帰確認 |
| legacy_v02_dev | v0.2のdev 138件。同じ例での回帰確認 |
| legacy_v02_test | v0.2のtest 139件。同じ例での回帰確認 |

旧1577行は元の内容を保持する。旧trainはtrainに残し、旧評価4セットは順序とJSONLバイト列も保持する。MASSIVEの公式partitionと出典情報も保持し、旧評価側の行はlegacyへ対応付ける。新評価にMASSIVEの別partitionを再分割して足すことはしない。

## 固定した学習と選択

- `sbintuitions/modernbert-ja-30m`、revision `8cb03f54cb9e30e72459e5f1cedc6d89c7d8dcb5`。
- seed 42/43/44 × learning rate 2e-5/5e-5の6試行。各10 epoch、batch 16、max 128 token、float32、SDPA、TF32なし。
- モデル入力は`text`だけ。slots・注釈・family・画面情報は入力しない。長すぎる入力は黙って切り詰めずエラーにする。
- 各試行のepochはdev macro F1、同率ならdev loss、さらに早いepochで選ぶ。共通学習率は3 seedのdev結果で選ぶ。
- 選択された3 checkpointを保存する。新devだけで主評価のseedを1つ確定し、その後にtestを予測する。testを見て一番良いseedに差し替えない。
- 旧版との比較では同じID・本文・goldの保存予測を使う。新testの難しさが変わるため、v0.3の88.64%との差だけを改善量と呼ばない。

## 確認する結果

全19分類のaccuracy、macro F1、混同行列、誤分類本文、全確率、seed間のばらつきに加え、単一dispatchからcompoundへの誤り、compoundから単一dispatchへの誤り、compound予測のprecisionを記録する。分母0の率はnullとする。

95%の目標判定は、事前に選んだ主評価モデルの新test accuracyに限る。新評価は合成の日本語テキストであり、実利用者の音声・ASR・画面に応じた引数解決・アプリ実行の評価ではない。小さいラベル別件数での率は不安定であり、合格しても自動採用しない。準備時点で学習や推論は実行していない。

Colab入力一式には出典、採用・除外記録、元データのハッシュ、全7 split、固定コード、テストを含める。結果ZIPには選択した3モデル、6試行の履歴、全7 splitの予測と検証結果を保存する。旧v0.3のコードも同版フォルダに固定しており、旧結果を新コードで読み替えない。
