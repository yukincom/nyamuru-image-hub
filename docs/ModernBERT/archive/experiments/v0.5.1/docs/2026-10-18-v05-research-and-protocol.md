# v0.5：最近の研究と、データを固定した学習方法の比較

2026-10-18。対象はニャムル音声操作の発話本文だけを使う19分類。v0.4のprimaryは59/73（80.82%）、3 seed平均81.28%。trainがほぼ100%であることだけから、原因を過学習やモデルの大きさに断定しない。

## 調べた研究と採否

| 研究 | 確認した内容 | 今回の扱い |
|---|---|---|
| [DDAIR, EACL 2026年3月](https://aclanthology.org/2026.eacl-short.20/) | 生成文が別intentの中心に近い場合を検出し、再生成または除去する。2/5-shot＋10合成例、15回の平均Macro F1。BANKING77/CLINC150では再生成、MPGTでは除去が有利。どの処理も一律に効くわけではない。 | 合成データの曖昧さを点検する次段階の候補。今回のloss比較にデータ変更を混ぜない。 |
| [EliDecide, AAAI 2026](https://arxiv.org/html/2511.16685v2) | 既知クラスの表現と楕円体境界で未知intentを検出。OOSの既知クラス率50%で、同じ境界方式のSoftmax表現→SupCon表現がMacro F1 87.25→88.57。 | 今回の`not_command`等は教師付きの既知ラベル。未知拒否へ置換すると意味が変わる。追加境界・別学習段階も必要なため保留。[著者実装](https://github.com/thuiar/TEXTOIR)は確認、未実行。 |
| [CUC, COLING 2025年1月](https://aclanthology.org/2025.coling-main.151/) | 混同するintent間の違いを生成条件にし、検証とfeedbackを反復。BANKING77 5-shotの同一系ablationでVanilla 77.91→完成84.41。追加教師情報を使う実験であり、lossだけの改善ではない。 | 境界対を作る参考。テスト誤りを生成材料に使った後は独立評価とは呼べない。公式実装は限定調査で確認できなかった。 |
| [BERT＋R-Drop, SemEval 2025年7月](https://aclanthology.org/2025.semeval-1.248/) | 英語のpromise verificationへ二視点とKL正則化を応用。Table 4にR-Drop有無の比較があり、4タスクとも有りが高い。ただし同じ二視点CEを対照にしてKLだけを分離する比較ではない。 | 最近の応用例として参照。この論文から今回の改善幅を見積もらない。 |
| [R-Drop, NeurIPS 2021](https://arxiv.org/abs/2106.14448) | 同じ入力のdropoutによる二つの予測に対し、双方向KLを小さくする。学習時のみ追加計算し、通常の分類器として推論できる。[著者実装](https://github.com/dropreg/R-Drop)の汎用例を確認。 | 今回の実装候補。新しい手法そのものとは称さず、最近の研究も比較した上で、データ固定・小変更で検証できる方法として選んだ。 |

[EMNLP 2025の小型特化モデル比較](https://aclanthology.org/2025.emnlp-main.9/)も参照した。複数のモデルと分類タスクで性能のばらつきを考慮しており、単一seedの最良値だけを示さない理由になる。そこでの必要ラベル数を今回へ流用しない。

詳細な調査記録は[recent-intent-research.json](2026-10-18-recent-intent-research.json)。英語・未知クラス検出・異なるデータ量での報告値を、日本語19分類の期待改善値には換算しない。今回の方式はR-Dropのタスクへの適用であり、他論文の完全再現ではない。

## 事前に固定する比較

既存`train.py`、同じエンコード、同じdev選択、同じ保存済み予測検証器を再利用する。`comparison.py`はこれを条件ごとに呼ぶ調整役で、別の学習ループは持たない。旧版の凍結コード・入力・モデル・結果は変更しない。

| 条件 | dropout | 学習時の予測 | 損失 |
|---|---:|---:|---|
| baseline | 0 | 1回 | 通常のCE |
| dropout_2view | 0.1 | 同じ入力を2回 | 二つのCEの平均 |
| rdrop | 0.1 | 同じ入力を2回 | 二つのCEの平均＋対称KL（係数1） |

実際のv0.4 checkpointのattention/embedding/MLP/classifier dropoutはすべて0。後二条件ではこの4項目を0.1に明示し、保存configにも検証をかける。対照も二視点に揃えることで、`dropout_2view → rdrop`ではKLの有無だけを変える。`baseline → dropout_2view`はdropoutと二視点平均の複合変更で、通常の一視点dropoutだけの効果とは称さない。

式は `0.5*(mean CE(z1,y)+mean CE(z2,y)) + α*0.5*(mean KL(p1||p2)+mean KL(p2||p1))`。KLはクラス方向に和、元の例方向に平均。両方の分布へ勾配を流す。著者READMEの汎用実装と同じ二視点CE平均を使い、KLは例数で正規化する。原著の式との係数尺度を混同しない。`α=1`と`p=0.1`は事前に固定する探索条件であり、この日本語データで最適と確認した値ではない。

trainはv0.4の1,296件、devは68件、testは73件のまま。旧v0.3のdev88/test132、旧v0.2のdev138/test139を含め、7 split・1,934件すべて原文・gold・順序・バイト列を維持する。文の追加、ラベル変更、プロンプト変更はない。既存のtokenization-checkも同じデータ・revision・tokenizerの記録として維持する。

全条件で `sbintuitions/modernbert-ja-30m`、revision `8cb03f54cb9e30e72459e5f1cedc6d89c7d8dcb5`。3 seed（42/43/44）×2学習率（2e-5/5e-5）×10 epoch、batch16、max128、float32、SDPA、AdamW、weight decay 0.01、warmup0、linear schedule。合計18試行・各条件3 checkpoint、計9モデルを保存。追加計算である二視点分を隠さず、同期した学習時間・評価時間・GPUピークメモリを記録する。

## 選択と評価の順序

1. 各条件で6試行を学習。各epochのdev Macro F1で最良epochを選び、dev loss、早いepoch、事前の試行順で同点を解く。追加損失は学習時だけで、dev/testは全条件とも一視点・通常CE。
2. 条件ごとに、3 seedの最良dev Macro F1平均で一つの共通学習率を選ぶ。学習率間の同点は既存規則どおり。
3. 全条件の学習を終えてから、選択済み学習率での3 seedのdev Macro F1平均で手法を選ぶ。同点なら平均dev CE、平均epoch、上表の条件順。primary seedはその手法内のdevで選ぶ。
4. 6本ずつの全dev履歴から選択を再計算し、条件・選択ファイル・checkpoint一式のハッシュと方法選択時刻を保存する。ここまでtest予測を作らない。
5. その後で9 checkpointを評価する。受領後も保存予測17,406件、設定、分割、全履歴、選択、重みを照合する。比較には全seedを出し、test首位への選び直しをしない。

v0.4のtest73件は既に読んでいるので、今後は**回帰診断**である。dev68件も再利用しており、モデル選択の楽観性と小標本の不安定さが残る。各クラス最低2件、testは1件で約1.37ポイント動く。3 seedの標本標準偏差は信頼区間ではない。

同じ例・同じseedの修復と回帰を両方保存する。単一→複数、複数→単一、非命令→操作、情報不足・対応外クラスの誤りも確認する。独立した未使用発話での95%達成判定は保留であり、今回のスコアが上がっても一般化精度やASR・アプリ実行の改善とは断定しない。自動採用しない。

## 検証範囲

準備時に損失の対称性・正規化・有限勾配、実ModernBERT構造での学習時二視点／評価時一視点、通常CEとの一致、保存再読込、dev限定選択と既読testの評価資格を検査する。さらに一時領域の極小モデルで、条件別学習→選択凍結→評価→検証→ZIP保存の全経路を確認する。これは実モデルの精度実験には数えない。

Colabでの実際の30mモデルによる18試行、CUDA実行、改善の有無はこの準備資料には含まれない。実行後の結果ZIPで検証する。
