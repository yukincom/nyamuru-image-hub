# シリーズ人物資料と照合特徴

シリーズを指定して人物設定と資料画像を保存し、各話のラフな人物を本番用キャラクターへ照合するための土台です。現在はシリーズ台帳の作成・読込・編集と、照合に使う外見特徴の抽出までを提供します。コマ内の人物名を自動入力する照合処理は次段階の機能です。

## 操作の流れ

1. 新規作成でシリーズ名を入力するか、保存済みシリーズを選びます。
2. 編集画面の「人物」を開き、「シリーズ共通」タブで人物を追加します。
3. 人物名、人物像、基準頭身を入力して「シリーズ資料を保存」を押します。
4. キャラクターデザイン画像を1枚以上追加し、正面・背面・横・斜め・表情・衣装などの種別と代表画像を指定します。
5. 必要な画像だけ「特徴を抽出」を押します。
6. 髪、顔、輪郭、服装、装飾、曖昧なデザインの抽出結果を修正・削除し、「特徴を追加」で人物設定へ反映します。
7. 誤りや不要な候補を各欄で直し、シリーズ資料を保存します。

「この話だけ」タブの人物は、その話のOMNYには保存されますがシリーズ台帳へは入りません。

## 照合特徴の方針

VLMの返答は、画像で直接確認できる`observed`と、単純な線画から補助的に読んだ`inferred`へ分けます。推定は事実として扱わず、人間が確認して修正します。

登録対象は本番用キャラクターデザイン資料です。生成工程の中間画像をアプリが自動判別することはないため、照合に使う資料だけを利用者が選び、「特徴を抽出」を明示実行します。

照合特徴に含める対象は次のとおりです。

- 髪型、前髪、長さ、分け目など
- 顔の輪郭と恒常的な顔パーツ
- 全身シルエットや衣装の形
- 服装とアクセサリー
- 画像だけでは断定できないデザイン上の候補

ポーズ、表情、視点、作画テイスト、物語上の性格、年齢、性別、等身は含めません。等身はキャラクター設定の`default_proportion.head_count`を正とします。

## OMNYの分離

シリーズ台帳は`manga.meta.document_type: series-catalog`のOMNYとして、各話とは別に保存します。`meta.format`は完成画像の色形式として独立して保持します。次の情報をシリーズ台帳へ持たせます。

- `characters[].scope: series`
- 人物の`catalog_id`、`aliases`、`default_proportion.head_count`、`recognition`
- 人物資料の`materials[].catalog_id`、`character_catalog_id`、`view`、`source_image`

各話のストーリーOMNYには、シリーズ人物の安定IDと照合用テキスト特徴を残します。ローカル画像の`source_image`はストーリーOMNYへ含めないため、他環境へ渡したファイルに端末内パスは入りません。シリーズ台帳を再読込すると、安定IDを使って画像資料との対応を復元します。

## 保存と競合

同じ話の保存要求は順番に処理し、保存待ちの間に進んだ編集を古い状態で巻き戻しません。シリーズ台帳は既存の別話の項目を残したまま、現在の話が所有する項目を追加・更新します。画像資料の削除は明示操作だけで台帳へ反映します。

保存処理が台帳を読み込んだ後、別の画面や別の話が先に同じ台帳を更新した場合は、リビジョンが一致しないため保存を停止します。画面を再読込し、両方の内容を確認してから保存してください。

既定の保存場所は次です。

```text
~/Library/Application Support/Nyamuru Manga Name Studio/series-common/<series-id>/
```

## ローカル解析の境界

資料画像を選択・保存しただけではVLM解析しません。「特徴を抽出」を押した画像1枚だけを`127.0.0.1`のローカルbridgeへ渡します。抽出結果は自動反映せず、利用者が編集してから追加します。モデルの自動ダウンロード、外部サービスへの送信、人物LoRAの自動学習は行いません。

bridgeとVLMの準備は [LOCAL_VISION_BRIDGE.md](./LOCAL_VISION_BRIDGE.md) を参照してください。
