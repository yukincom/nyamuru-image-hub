# 漫画仕上げの実装計画

2026-11-02。文書で合意した制作手順を、既存機能に接続する順序を示す。生成候補（第1・2節）と自作フォルダーの入れ子は実装済み。漫画仕上げ処理は未実装。[漫画仕上げ仕様](MANGA_FINISH_SPEC.md)

## 1. 緑背景の5候補を透過して表示

人物の3参照・5シードの生成を使う。各PNGの取得時に、既存の `scripts/qwen_background.py` の `remove_chroma_background` を1回適用し、候補番号と対応付ける。緑の色判定はRGBの段階で行い、キー設定・原稿dpi・コマのクリップ範囲を引き継ぐ。生成・参照の寸法は既存の設定を使う。

人物の新ジョブは取得時に `candidate-N-cutout.png` を保存し、一覧・拡大プレビュー・採用処理が同じ透過済み画像を読む。`candidate_cutout` を保存したジョブだけが複数採用を使う。画面の再表示や採用で二重に緑を抜かない。保存済みジョブは生成時の設定に従う。

完了条件は、取得した5枚が透過済みで候補一覧に揃い、各プレビューが採用時に受け取る画像と一致すること。

## 2. 複数採用と未採用画像の削除

既存の生成画面、ローカルbridge、ジョブ保存、画像追加を使う。単一の採用番号と出力を採用集合に拡張し、選択した透過画像を元のフォルダーへ1枚ずつ独立したレイヤーとしてまとめて追加する。5枚が完成し、1枚以上を選択した時点で追加可能とする。

生成画像の初期名は作品へ実際に挿入するときに割り当てる。候補番号やファイル名と分けて、既存の編集確定・名前変更の経路を使い、作品の `generated_image_sequence` を確定時だけ進めて、「生成 01」「生成 02」…と生成画像の追加分だけを数える。選択の変更、追加の失敗、通常の画像読み込みでは通番を進めない。追加の再試行やRedoは同じレイヤーを使い、改名のUndo/Redoは履歴に記録した名前を復元する。

選択分すべての追加が成功した後で、未採用候補の画像実体をニャムルとComfyUIの両側から削除する。生成時にジョブ・候補番号とComfyUIが返した実際の保存先を対応付ける。同梱のComfyUI拡張の `/nyamuru/outputs/delete` で、完了したpromptの出力メタデータと一致する未採用PNGだけを削除する。追加に失敗したら候補を保持し、削除だけが失敗した場合は追加済みレイヤーを保って対象の削除だけを再試行できるようにする。

完了条件の例として、候補2と4の確定で元フォルダーに2レイヤーが入り、候補1・3・5のローカル画像と該当するComfyUI出力が消える。Undo、再表示、再試行で重複追加や他の出力の削除が起きない。ここで利用者は原稿上の各候補を比較し、そのまま使用・非表示・削除・手直しを選べる。

第1・2節の検証結果は[実装記録](2026-11-02-multi-candidates.md)を参照。

## 3. 同じコマのラスターを複数選択して仕上げる

ツールパレットの空き位置に、既存の `PaintToolButton` と単色のsparklesアイコンで「漫画仕上げ」を置く。レイヤーパレットの選択経路を複数のラスターへ拡張する。対象は同じコマ内で選んだ生成画像・読み込み画像・通常の手描きラスター。1枚選択と複数選択は同じ操作を使い、複数選択でも✨の実行は1回とする。

選択した各レイヤーのID、手直しを反映した画素・alpha・配置・重なり順を実行時に固定する。既存のComfyUI接続でMangaScreenの線・ベタとグレーの陰影を取り出し、網点を焼く前で処理を終える。導入済みの `MangaFinish` は合成画像を返すため、中間結果を個別に出す接続を加える。複数選択を同時に確定する操作と、内部で各画像の処理を進める順序は独立させる。

完了条件は、同じコマの生成画像・手描き・読み込み画像をまとめて選び、1回の実行で選択分を仕上げられること。入力に含まれるのは選択したラスターレイヤーの現在の内容だけとする。

## 4. 編集後の透明範囲で輪郭を整える

処理用に白へ合成する前に、編集済みレイヤーのalphaを確保する。仕上げ後はその透明・不透明の範囲を手掛かりに、輪郭付近だけを出力に合わせて調整する。全画面の白を探す既存の `remove_white_background` はこの用途と異なるため、境界調整はこの仕上げ経路に集約する。決め打ちの輪郭幅や、新しい品質検査は設けない。

完了条件の例は、白く塗り足した肩は残り、腕の間の透明な穴は開いたまま、髪の縁に白いにじみが残らないこと。元のぼかしを戻さず、各出力の境界が一致すること。生成画像と手動取り込み画像に同じ処理を使う。

## 5. 「仕上げ✨」への置き換えとトーン表示

元レイヤーごとに独立した「仕上げ✨」フォルダーを1個作り、既存のフォルダー名変更操作を使う。その入力から得た線・ベタ・グレーの陰影・白下地を格納する。各フォルダーは入力と同じ親・重なり順に置き、紙面上の位置・大きさ・画素寸法を保持する。選択分の置き換えをまとめて確定し、1回のUndoにする。失敗や適用前のキャンセルでは全入力がその場に残る。

網点の生成はニャムルの `src/lib/paintTone.ts` に一本化する。既存の描画処理は描画範囲のオフセット、トーン原点、原稿dpi、線数、角度を使う。仕上げ由来の陰影には、コマや人物内部の描画座標へ用紙の共通原点を換算して渡す。異なる切り出し位置の人物でも同じ紙面座標・線数・角度で網点が一致することを確認する。独立した網点画像を各人物の左上から作らない。

自作フォルダー内の仕上げには、以下の順で既存のツリー、移動、履歴、保存を拡張する。入れ子は仕上げ画像の処理とは独立した編集機能とし、構造の確認には通常のラスターレイヤーと画像資産を使える。

### 5a. 収納形式と順序を決める

1. `PaintFolder` に任意の `parentFolderId` を加える。親IDは同じ `PaintDocument` 内の直接の親を参照する。人物や背景などの描画対象は従来の所有関係で表し、自作フォルダーの親IDと区別する。各レイヤーは既存の `folderId` を使う。親IDを持たない既存フォルダーは最上位として読める。
2. `paintLayerTree` が直下のレイヤーと子フォルダーを再帰的に組み立て、`withPaintLayerTree` が編集結果を既存の `layers` と `folders` に書き戻す。ツリーは編集・表示用の派生値。描画用の葉は今と同じく `layers` に下から上へ並べ、各フォルダーの子孫の葉を連続した範囲にする。
3. 順序の書き戻しでは、兄弟を下から上に走査し、フォルダーを訪れた時点の「すでに出力した葉の数」を既存の `position` に入れる。葉を含むフォルダーでは先頭の葉の位置、空フォルダーでは挿入境界になる。同じ境界を共有する兄弟フォルダーは `folders` の保存順で区別する。復元時は同じ親の直下だけを比較する。位置が葉の添字と一致する空フォルダーは、その葉の直前（下から上の順で先）に置く。パレットではこの兄弟順を逆順に表示する。空の子フォルダーだけを持つ親もこの規則で復元できる。
4. `validatePaintDocument` の既存検証で親IDの実在と循環のない所属を扱う。入力の祖先が自分自身を指す構造は受け付けない。親名からの推測や別の順序台帳は不要。現在のレイヤー・フォルダー数の上限は、描画対象内の総数に適用する。

### 5b. 移動と仕上げ置き換えを同じツリー操作に接続する

- `movePaintLayer`、`movePaintFolder` は移動元の直下から項目を外し、ドロップ先の直接の親と兄弟位置へ挿入する。中央へのドロップはフォルダー内の最上段、上下へのドロップは対象と同じ親。フォルダー移動では部分ツリーを丸ごと扱う。取り外す前に移動先を識別し、同一親内の上下入れ替えにも同じ規則を用いる。
- 既存の `movePaintEntry` が描画対象をまたぐ場合は、フォルダー・子孫のレイヤー・空の子フォルダーを一緒に移す。紙面座標・クリップ・トーン原点の換算は既存の変換で葉ごとに1回行う。フォルダー移動だけでトーンの位相をずらさない。対象内の移動には座標変換は不要。
- `PaintLayerPalette` と `PageLayerPalette` は同じ再帰ツリーを表示し、既存の `move-layer`／`move-folder` に親と挿入位置が届くようにする。目・ロック判定は `paintLock.ts` で祖先まで辿る。文字などの前後の区分（`aboveNative`）は既存の移動先の区分を子孫に揃える。フォルダー解除では直下の項目を1段上へ挿入し、削除では子孫を含む単位を既存の削除履歴へ渡す。
- 一括仕上げは、選択した各元レイヤーのIDを、その親の同じ兄弟位置で「仕上げ✨」の部分ツリーへ置換する。全結果が揃ってから既存の編集履歴に1回で確定する。例えば同じ親の2枚の間に効果線があれば、効果線は結果の間に残る。異なる親から選んだ場合も、親ごとに元の位置を使う。処理中に親や対象が変わり適用できない場合は、生成済み結果を別の位置に挿入せず作品を確定前の状態に保つ。

### 5c. 既存のUndo/Redoと作品保存を往復させる

- `PaintEditor` と `App` の既存の編集確定／共有履歴に、1操作分の前後のツリーを渡す。ドラッグ中の表示はプレビューで、ドロップ確定時だけ移動を記録する。Undo/Redoで同じID、親、兄弟順、紙面座標、画像資産が戻り、別の画像処理や採番は起きない。
- 通常の保存操作が描画編集中の変更を確定した後、`createProjectSnapshot` に `PaintDocument` の親ID・順序・配置を含める。通常の作品フォルダーを開く `restoreProjectSnapshot` と既存のYAML読込で同じ状態を復元する。LAN側でも共有しているスナップショット経路を使う。用紙の保存形式やPNGに別の階層情報を付け足す必要はない。
- 通常再読込では保存したIDを引き継ぐ。別の描画領域へ取り込む際など、既存処理が新しいIDへ写す経路では、フォルダーの親IDとレイヤーの所属IDの両方を同じ対応表で写す。名前・配列の偶然の並び・サムネイルに頼ってツリーを再構築しない。

### 5d. 実装後に確認する制作操作

| 制作操作 | 合格条件 |
|---|---|
| 自作フォルダー内の離れた2枚を一括仕上げし、Undo→Redo | 元の2か所に別々の「仕上げ✨」ができ、間の未選択レイヤーと別の親の項目は元の重なり順・座標にある。Undoは元の2枚、Redoは同じIDの結果を復元する。 |
| 同名の「仕上げ✨」の一方だけを別の自作フォルダーの中へ、次に親の外へ移し、それぞれUndo→Redo | 指定した枝だけが全子孫・空フォルダーを伴って移る。ドラッグ1回につき履歴1回。紙面上の位置・大きさとトーンの原点が保たれる。自分自身・子孫へのドロップでは順序・履歴が変わらない。 |
| 内側のフォルダーを解除または削除し、Undo→Redo | 解除では直下の項目だけが1段上がり、削除では枝が消える。どちらも元の親・内部の順序へ戻せる。 |
| 移動後に通常どおり保存し、作品を閉じて開き直す | 同名の兄弟、同じ境界にある空フォルダー、改名した子、目・ロックを含む親子関係と順序が一致。キャンバス上の重なり、画像の位置・大きさ、トーンの位相も保存直前と一致する。再読込後に同名の一方だけを改名・移動して、もう一方とその子に影響しない。 |

これらは実装後の受入条件。保存・再読込は作品への明示的な保存からの往復、Undo/Redoは既存セッション内での編集履歴を確認する。

完了条件は、間に未選択レイヤーを挟んだ2枚を選ぶと、同じ位置・順序に別々の「仕上げ✨」ができること。各フォルダーと中のレイヤーを移動・編集・改名でき、Undoで手直し済みの入力に、Redoで確定済みの一括結果に戻れること。

## 6. 削除と画像実体の回収

レイヤーパレットで行うすべての削除を既存の作品履歴に通す。対象の種類によらず、現在の作品・Undo・Redoから参照される間は復元に必要な内容と画像を保持し、履歴上限の超過やRedo履歴の破棄で最後の参照がなくなったものを完全削除する。資料・別レイヤーなどの共有参照や、保存・取り込み中の既存の保護も同じ資産管理で扱う。[画像の保持と解放](2026-10-31-image-retention-ui.md)

完了条件は、削除したレイヤーやフォルダーを名前・所属・内容ごとUndoで戻せ、Redoで再び消せること。履歴内は実体が残り、履歴外に出て他の参照も消えた時点で専有する実体が回収されること。採用されず一度もレイヤーにならなかった候補の破棄は第2節に従う。

生成画像については、採用レイヤーとジョブ出力の対応を回収にも使う。最後の参照が落ちたときに、その項目だけが使うニャムル側とComfyUI側の出力複製も回収できるようにする。

説明はマニュアル側の `plans/2026-11-02-manga-finish.md` で管理する。段階ごとの確認は上記の制作操作に限る。ネーム読み取り、別機能のUIやレイアウト、事前の画質比較試作は今回の計画の対象外。
