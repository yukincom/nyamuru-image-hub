# LAN編集 — 2026-10-20

別のPCではブラウザーで編集し、作品はそのPCの `.nyamuru` ファイルへ保存します。文章LLM・画像解析・画像生成はMac Studioの既存環境を使います。編集PCへのモデルやNode.jsの導入は不要です。

## 起動と接続

1. Mac Studioで、普段使っている文章LLMを起動しておきます。
2. このリポジトリで `npm run lan` を実行します。画面の準備後に、HTTPSの接続URL、CA証明書の場所・SHA-256指紋が表示されます。
3. 初回だけ、下記のCA証明書を編集PCへ登録します。
4. 同じLANにある編集PCで、表示されたURLを開くと、そのまま編集画面に進みます。
5. 作業終了後はMac側の起動画面で `Ctrl+C`。LANサーバーと、この起動が所有する処理サービスを終了します。

接続コードとログイン操作は不要です。同じLAN内の端末から利用する自宅用の接続です。Macが停止・スリープ中はAI処理を利用できません。接続アドレス・ポートを変えるとブラウザーの作業キャッシュも別になるため、保存した作品ファイルを開いて続けてください。

通常は最初に見つけたLANアドレスの4322番を使います。別のアドレスを使うときは `npm run lan -- --host <MacのLANアドレス> --port 4322`。空いていないポートでは明示的に終了します。ルーターやファイアウォールの設定を自動で変更する処理はありません。

### Mac同士を有線で直結する場合

ルーターなしで直結すると、Ethernetには `169.254.x.x` のアドレスが自動設定されることがあります。これは同じ物理リンク上の通信に使う正常なアドレスです（[RFC 3927](https://www.rfc-editor.org/rfc/rfc3927.html)）。アプリはこの範囲もLANとして扱います。

Mac Studioの「システム設定 → ネットワーク → Ethernet」にあるIPを明示して起動します。たとえばEthernetが `169.254.224.71` なら `npm run lan -- --host 169.254.224.71` を実行し、編集用Macでは `https://169.254.224.71:4322/` を開きます。IPが変わった場合は現在の値を使ってください。初回の証明書登録は下記と同じです。接続元と接続先のMacには異なるIPが必要です。

Wi-Fiのインターネット接続は併用できます。ただし接続先にWi-Fi側のIPを使うと、有線直結を利用することにはなりません。複数の接続がある環境では、相手のEthernetのIPに対する実際の経路を確認します。`169.254` への経路がWi-Fiを選ぶ場合は、両Macの有線設定を確認してから対応を決め、アプリが自動で経路やWi-Fi設定を変更することはありません。リンク速度の1Gbpsと実際の転送速度は別です。

## 初回の証明書登録

ブラウザーのファイル保存・音声入力などを利用するため、LAN接続はHTTPSです。HTTPでの起動や証明書検証の無効化は行いません。

Mac側で生成する公開CA証明書は `.local-vision/lan-tls/nyamuru-lan-ca.crt` です。このファイルだけを、AirDrop・USBなどで編集PCへ渡します。同じフォルダの `.key` ファイルは渡さないでください。証明書のSHA-256指紋を起動画面の値と照合し、自分のMacで作成した証明書であることを確認します。

- **編集PCがMacの場合**：キーチェーンアクセスへ証明書を読み込み、対象の「Nyamuru LAN private CA」を開いて「信頼」のSSL設定を変更します。操作の説明は [Appleの証明書の信頼設定](https://support.apple.com/ja-jp/guide/keychain-access/kyca11871/mac) を参照してください。
- **編集PCがWindowsの場合**：`certmgr.msc` で現在のユーザーの証明書管理を開き、「信頼されたルート証明機関」の「証明書」へ公開CA証明書をインポートします。保存先の範囲と指紋を確認する手順は [Microsoftの証明書管理](https://learn.microsoft.com/en-us/windows-server/identity/ad-cs/inspect-certificates-manage-certificate-stores) を参照してください。

登録は編集PC側で利用者が行います。アプリはOSの信頼設定を変更しません。登録後にブラウザーを開き直し、証明書エラーが出ない状態で接続します。

既存の証明書を使う場合は、Mac側で `NYAMURU_LAN_CERT` と `NYAMURU_LAN_KEY` の両方にファイルのパスを指定します。接続するIPまたはホスト名に有効な証明書が必要です。自動生成するサーバー証明書は1年、CAは5年で、IPが変わった場合や期限が近い場合は同じCAでサーバー証明書を作り直します。

## 作品の保存

「保存」または `⌘S / Ctrl+S` で、本文・コマ・フキダシ・作画設定・レイヤー・配置画像・3D背景・人物資料画像を1つの作品ファイルへ保存します。「ファイル」から「別名で保存」と「作品ファイルを開く」を使えます。

保存先を選ぶAPIが利用できるブラウザーでは、初回に選んだファイルへ上書きします。ファイルの外部更新を検出した場合は書込みを止め、別名保存を案内します。同じオリジンのタブ間は保存を排他制御し、ネイティブwriterにも排他モードを指定します。OS上の任意の別アプリとの完全な排他を保証するものではありません。

対応APIがないブラウザーでは、保存のたびに作品ファイルをダウンロードし、読込みにはファイル選択を使います。画面には「ダウンロードを開始しました」と表示します。保存場所とダウンロード完了はブラウザー側で確認してください。[保存先選択APIにはブラウザーごとの対応差があります](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)。作品ファイルの上限は192MiBです。

ブラウザー内の自動復元データやシリーズ一覧は作業用キャッシュです。別PC・別ブラウザーへ移る前や、サイトデータを消す前は作品ファイルを保存してください。人物設定画面の「保存」はブラウザー内のシリーズ台帳にも反映しますが、作品ファイルの更新は上部の「保存」で行います。

新規作成の途中の人物は、作成中の作品に保持します。途中で閉じた場合は破棄されます。作品作成後に上部の「保存」を実行してください。人物テキストや原作資料は編集PCのファイルから読み込めます。

## 既存作品を別PCへ持ち出す

Macの通常起動（`npm run dev`）で既存の作品フォルダを開き、「ファイル」→「持ち出し用の作品ファイルを保存」を使います。その `.nyamuru` を編集PCへ渡し、LAN画面で開きます。元の作品フォルダは更新しません。

OMNYのテキスト書出しとは別に、元画像や人物資料画像も同梱します。必要な画像が失われている場合は、欠けた作品ファイルを保存せずエラーを表示します。作品ファイルはMac自身のブラウザーでもLAN画面から編集できます。従来のMac作品フォルダへ戻す機能は含めていません。

## 処理の配置と制限

- `.nyamuru` と編集用キャッシュは編集PCに置きます。AIへ渡すテキストや画像は、必要な操作時にMacへ送信します。モデル・画像生成の履歴や高速化キャッシュはMacに残ります。
- HTTPS入口から、既存の画像解析・エージェント・音声・画像生成APIへ接続します。内部bridgeと文章LLMはloopbackのままです。LAN入口ではHost・Origin・接続元の確認を行い、許可した処理APIだけを通します。接続コード・ログインCookieは使用しません。
- Macの作品フォルダ選択、作品保存、スキャナー操作、シリーズフォルダ操作はLAN入口で拒否します。スキャン済み画像は編集PCの「画像を読み込む」から渡せます。Macフォルダの制作台帳を使う旧作画ラフ機能はLANでは利用できず、レイヤーの画像生成を使います。
- 画像生成は既存の仕組みを使うため、必要に応じて文章LLMを一時停止し、生成後に復帰します。通常の文章処理とLAN終了では、起動前からあるLLMを停止しません。
- 原文照合の一時的な資料バインド・手動判断は作品snapshotに含みません。必要な照合結果は画面からJSONで書き出してください。シナリオとして取り込んだ本文は作品に含まれます。
- 複数人の同時共同編集やアカウントごとのデータ分離は実装していません。
