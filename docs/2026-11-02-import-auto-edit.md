# ネーム解析から編集画面への自動遷移

2026-11-02。ページ設定の「解析開始」を押すと、全ページのコマ・文字・人物領域の解析、人物照合・姿勢・表情の読み取り、作品作成、編集画面への遷移まで順に進む。「編集開始」の追加操作は不要。

## 接続と失敗時の扱い

`App.tsx` の `analyzeNewLayouts` は全ページの結果を既存の `createNewDocument` へ渡す。同じ操作世代を引き継ぎ、処理中に操作可能なidle状態を挟まない。各ページ・人物の解析、切り抜き、保存、結果反映、スキャンの確定、ブリッジの解放は既存処理を使う。

コマ未検出や解析失敗のページがあれば、結果を表示してページ設定に留まる。解析中に閉じた操作の遅延応答は作成へ進まない。人物単位の読取失敗は既存の要確認として反映する。まっさらな作品・コマ割りテンプレートからの作成は既存入口を使う。

ページごとの検出結果・OCR記録、人物ごとの処理済み件数・現在の人物・経過時間の表示を継続する。

## 確認

- 関連Nodeテスト38件成功。画像入力・スキャンの両方で、解析開始から人物の表情文を反映した作品へ到達すること、推論待ちの0/1と完了時の1/1、二重開始の拒否を確認。
- コマ未検出、解析API失敗、取消し、古い世代、保存先準備失敗で自動遷移しないことを確認。
- テストはAppの実ハンドラー、人物配置と結果反映、進捗コンポーネントを使い、検出・推論・画像切り抜き・書込は模擬。実画像を使った一連の実機操作は利用者確認待ち。
- 通常画面で選択済み4ページと「解析開始」の維持、「編集開始」がないことを確認。画面の再読込は不要。

全件テストとビルドは利用者の確認後に実施する。

## 原画プレビューの表示寿命

開発中の画面更新でAppの終了処理が実行されると、stateに保存したblob URLだけが失効し、元Fileが残っていても切り替え先のプレビューを表示できない場合があった。表示済みのサムネイルにはキャッシュ画像が残るため、フォーカス画像だけが壊れることもある。

原画サムネイルとフォーカスは `NewLayoutSourceImage` が元Fileから表示用URLを作り、表示の終了・Fileの変更時に所有URLを解放する。effectが再実行された場合も新しいURLを作る。Appの解析結果・入力stateにはURLを保持しない。

局所Node31件成功。実componentのeffect再実行・ページ切替・URL解放を検証し、実ブラウザーでも合成PNG2枚のdecode・切替・破棄後の再表示を確認した。解析・推論への変更はない。
