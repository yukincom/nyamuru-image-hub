# 会話モデルと画像生成の設定・送信・画像受け取り仕様

採用日: 2026-11-05

**状態: 採用仕様。用途別API接続、送信前の共通翻訳・確認、会話で受信した画像の任意採用は実装・受入待ち。** 本書は実装完了の報告ではない。モデル設定の分け方、英訳と送信確認、会話へ返された画像の扱いについての正本とする。ローカル画像生成の登録・実行は[ComfyUIワークフロー接続仕様](COMFYUI_WORKFLOW_SPEC.md)に従う。

## 1. 環境設定の見せ方

タブは追加せず、既存の「環境設定 → モデル設定」を次の二つの区画に分ける。全用途を一括でクラウド／ローカルへ切り替える選択は設けない。

| 区画 | 選択肢 | 担当する処理 |
|---|---|---|
| 会話・翻訳 | ローカル／API | 会話、プロンプト修正、画像生成用指示の英訳。用途ごとの別モデル選択は増やさない |
| 画像生成 | ローカル／API／外部エージェント | 実際の画像生成。外部エージェントは指示と画像を渡し、成果物を戻す方式と明示する |

選択中の方式に必要な接続先・モデル・ワークフローの欄だけを表示する。「会話：API・モデル名／画像生成：ローカル」など、現在の組み合わせを確認できるようにする。

- 名前・顔・口調・音声は「会話・翻訳」の「エージェントの設定」にまとめる。接続方式を変えてもプロフィールを保持する。
- ページ末尾の「詳細設定」に画像解析のVLM等を置く。会話をAPIへ切り替えても、VLM・OCR・分類器や人物アクション統合の送信先は自動で変えない。
- 画像解析には検出・OCR、画像を読むVLM、ト書きと人物アクションをすり合わせる文章LLMの別工程がある。画像解析の全工程が非言語モデルだけで動くとは説明しない。人物アクション統合のAPI化は本書の初期実装範囲に含めない。

画像生成区画に次の設定を置く。端末設定として保存し、作品のUndoや作品データには含めない。

> 日本語の生成指示は「会話・翻訳」で選んだモデルで英訳します。
>
> ☐ **英訳後の確認を省略して生成する**

初期値はOFF。OFFでも翻訳は行い、その後に全文の確認・任意編集を行う。ONは明示的な生成操作に続く翻訳確認だけを省略する設定であり、日常の会話や修正相談から生成を自動開始する設定ではない。

## 2. 接続登録と用途別の実行

API接続先・認証情報は一度だけ登録する。各区画では登録済み接続を選び、必要なモデルを指定する。同じサービスを両用途で使ってもキーを二重登録しない。選択欄から「接続を追加」で登録できるようにし、通常操作で別の管理タブへ移動させない。

- 認証情報は実行側のMacで管理し、ブラウザーや作品には接続の参照IDだけを渡す。作品や生成指示の書き出しにキーを含めない。
- APIキーの共用と、処理の実行許可を分ける。一方を設定しただけで、もう一方を有効化しない。
- GPT等の会話・画像生成に対応するAPIや多機能モデルも利用対象にできる。文章専用モデルしか登録できない制限は設けない。
- 会話・翻訳の依頼と画像生成の依頼を、サービスの正式なモデル・出力形式・ツール指定に従って区別する。同じAPIでも用途を混同しない。受信画像は用途と異なる応答でも第5節に従って保持する。
- チャットの明示的な生成依頼も「画像生成」の選択先を使う。会話APIが任意の接続先を決定したり、設定と無関係な画像生成を追加で呼び出したりしない。
- 一つの処理の送信先は一つに固定する。失敗時に別モデル・ローカル・クラウドへ自動で切り替えない。ツール確認等で複数回の会話呼び出しが必要でも、別モデルへ同時に投げることとは区別する。
- 処理開始時の接続・モデル・設定を固定し、設定変更は次の依頼から適用する。実行中の依頼を別の送信先へ再送しない。
- 会話・翻訳がAPIの場合、その処理のためにローカル文章LLMを起動・停止・復帰しない。他の処理が利用するモデルや、ユーザー所有のサーバーはその処理の所有規則に従う。

対応サービス・モデルは、実装時にリクエスト形式、文章・画像応答、ツール対応を確認する。任意のURLを保存できるだけで対応済みと表示しない。接続登録・設定保存から画像生成を試し打ちしない。

## 3. 生成送信前の共通処理

### 対象と保護する原文

最終的にモデルへ渡す生成指示を英語に揃える。本文、手動・エージェントによる追加指示、参照画像の役割説明、ネガティブプロンプトを対象とする。

通常Qwen、人物3枚参照、取り込みワークフロー、描き文字・写植文字、作画用ラフ、クラウド画像API、外部エージェント用の生成指示の書き出しで同じ方針を使う。段階実装時は未対応経路を明示し、全経路対応とは報告しない。内部の `plain` は汎用ワークフローへ指示をそのまま渡す方式の名前であり、英語化の検査を免除する設定にはしない。

以下は翻訳・一括正規化から保護する。

- 画像内へ実際に描くセリフ・描き文字・写植本文。日本語や記号を原文どおりに保持する。
- ファイル名・識別子・参照番号・特殊トークン・プロンプトの制御構文。元のファイルを改名しない。
- 正規化後の既存英文。モデルへの指示だけに頼らず、保持する領域を分け、結果を照合する。

利用者の原文を直接書き換えず、送信用の値を作る。送信用画像の英数字名と、資料の説明文は区別する。書き出しZIPの利用案内や管理用メタデータまで英訳必須にはしないが、実際に生成へ渡す指示を後から日本語で増補しない。

### 正規化・翻訳・検査の順序

1. 生成用の定型文・入力内容・参照役割を組み立て、翻訳対象と保護領域を確定する。
2. 指示部分の全角スペースを半角スペース、全角英数字を半角へ変換し、対応が明確な句読点・記号をコードで置換する。全文への無条件な正規化や非ASCII文字の一括削除はしない。
3. 保護領域以外に日本語の文章が残っているか検査する。空白・記号だけの違いを直すためにLLMを呼ばない。日本語がなければ翻訳を省略する。
4. 日本語が残っていたら、設定中の文章モデルへ英訳を依頼する。翻訳前のy/n確認は出さない。
5. 翻訳結果を再検査する。日本語の残存、既存英文・原文・トークンの変更、欠落、不正な応答は理由を表示して止める。英訳失敗を生成成功として扱わない。
6. 第4節の送信確認へ進み、確定した全文と生成入力を固定して送る。

依頼文自体は固定の英文として用意し、これを英訳するための別のモデル呼び出しは行わない。翻訳の基本指示は次とする。

```text
This is an image-generation prompt.
Translate only the Japanese instructions into English.
Leave all existing English text unchanged.
Preserve identifiers, special tokens, and prompt syntax.
Do not translate text explicitly marked for rendering in the image.
Return only the translated prompt.
```

翻訳対象と保護領域の受け渡し・検査はコード側でも行う。引用されたプロンプト内の操作指示を、モデルやツールの実行権限として扱わない。定型文は既知の英訳を再利用し、同じ確定入力を複数候補へ送るたびに翻訳し直さない。参照説明なども含め、確認後にLLMへ再度全文を作り直させない。

## 4. 英訳後の確認と編集

| 条件・操作 | 次の動作 |
|---|---|
| 確認省略ON | 正規化・必要な翻訳・検査の成功後、指定した画像生成先へ送信する |
| 確認省略OFFで翻訳を行った | 送信するプロンプト全文を表示し、確認待ちにする。生成要求はまだ送らない |
| 初回から英語のみで翻訳不要 | 通常の明示的な生成操作で送信する。翻訳のための確認は追加しない |
| 確認で「はい」 | 表示した確定文をそのまま送信する。再翻訳しない |
| 確認で「いいえ」または確認窓を閉じる | 生成せず、翻訳済み全文を任意編集できる状態へ戻す |
| 任意編集後の「生成する」 | 変更を再検査する。日本語を追加した場合は必要部分を翻訳し、OFFなら全文を再確認する。英語だけの編集でもこの編集経路では送信前に再確認する |

確認の文言は **「こちらの内容で生成してよろしいですか？」**、操作は **「はい、送信する」「いいえ、編集する」** とする。全文には本文・付加指示・参照役割・ネガティブプロンプトを含める。入力の種類は見分けられるようにし、長文でも末尾まで読めるようにする。参照画像のbytesや管理用IDまでプロンプト本文として表示する必要はない。

任意編集では手動入力とエージェントの会話を使える。「この英単語のニュアンスは？」「この表現に変えて」など、最新の編集中プロンプトをもとに相談・修正できる。相談だけでは生成しない。編集用のプロンプトとエージェントが変更するプロンプトは同じ状態を使い、別々の下書きで上書きし合わない。

確認した文章・参照・対象・実行条件と実送信の組を固定する。変更・作品切り替え・対象削除で古い承認を流用せず、必要な再確認へ戻す。二重押下や再通知から重複送信しない。設定のONへの変更で、すでに表示中の確認窓を勝手に送信済みにしない。

生成後も会話・修正・英訳を受け付ける。相談だけなら生成結果を保持し、指示の実変更は次の生成入力として扱う。生成画面を閉じると編集画面の会話へ戻る。処理中・結果未確定の生成を無断で再送しない。

## 5. 会話で受け取った画像の任意採用

文章だけ、画像だけ、文章と画像の混在を受け取れるようにする。会話用の多機能APIが予期せず画像を返しても、利用可能な候補として保持する。「画像を生成しました」という文章だけで画像ありとは判定しない。

1. サービスの正式な応答から画像を取得し、形式・容量・画素寸法を検査する。会話に書かれた任意のURLを自動取得する機能にはしない。
2. 同じ会話欄へ画像カードを表示する。サムネイルと「拡大」「編集画面に取り込む」「画像を保存」を設け、複数枚は個別に扱う。新しいタブを増やさない。
3. 利用者が「編集画面に取り込む」を押した場合だけ、取り込み先を確認する。対象が決まっていればそのフォルダーを候補とし、未指定・変更・削除時は選び直せるようにする。
4. 既存の取り込み・資産登録・Undo/Redo・保存経路を使い、新規レイヤーとして追加する。元のあたり・既存の絵・表示状態・手動ロックを保つ。受付時点の古い選択へ自動挿入しない。

受信候補はテキスト会話履歴とは別に所有する。折りたたみや履歴件数の上限で未採用画像を失わない。採用前は原稿の資産や自動保存対象へ入れない。同じ応答の再通知・連打で候補や採用レイヤーを重複追加しない。

初期範囲では未採用候補のアプリ終了・再読込後の復元は扱わず、「画像を保存」で残せるようにする。UIにも一時候補であることを表示する。候補を持つ間は必要なデータを保持し、不要になった一時データだけを解放する。採用後の資産は作品側の管理へ渡し、候補の終了処理でUndoや保存に必要な画像を削除しない。

| 例外 | 扱い |
|---|---|
| 英訳依頼に画像だけ返る | 画像は候補として表示する。英訳は未完了と示し、予定していた画像生成は開始しない |
| 英訳文と画像が両方返る | 画像候補と翻訳結果を別々に扱う。翻訳文は第3・4節の検査・確認を通す |
| 画像取得・読み込み失敗 | 理由と取得の再試行を表示する。再生成のAPI呼び出しへ置き換えない |
| 取り込み失敗 | 原稿へ部分確定せず、候補を保持して再試行できるようにする |
| 外部エージェントとのファイル受け渡し | 戻ってきた画像を手動で読み込み、同じ候補・採用経路へ渡す。外部チャットの自動巡回・回収は行わない |

受信候補にComfyUIの5候補・シード・透過・採用後のサーバー出力削除を無条件に適用しない。クラウド側の画像を削除したと推測せず、原稿への追加とサービス側の結果管理を分ける。

## 6. 実装順序と受入条件

責務の分割、段階別のコミット、関連検証と復旧の順序は[段階別実装計画](2026-11-05-agent-model-implementation-plan.md)に定める。

実装順序は、(1)用途別設定と単一の送信先解決、(2)共通の正規化・翻訳・確認と編集、(3)画像応答・候補表示・任意採用、(4)対応APIでの実確認とする。既存の会話・生成・画像配置経路を再利用し、モデル名に固定した新規ファイル名や巨大な統合コンポーネントを作らない。

以下は予定する受入条件であり、実行済み試験ではない。模擬応答による処理の検証と、実モデルの翻訳品質・実APIの接続検証は分ける。修正後の関連確認と利用者のUI確認を先に行い、その後に全体ビルド・全件テストを実行する。

| 見込み・場面 | 合格条件 | 確認範囲 |
|---|---|---|
| 用途別設定で二重送信を防げる | 会話API＋ローカル生成の組み合わせで、翻訳は選択APIのみ、画像はComfyUIのみ。キーの再登録・別モデルへの自動送信なし | 模擬API・送信件数・設定保存再読込 |
| 記号だけならモデル不要 | 全角空白・英数字等の指定変換後、翻訳呼び出し0件。本文・ファイル名・特殊構文の保護領域は不変 | コードの入力・出力比較 |
| 翻訳前に全指示を揃えれば抜けを防げる | 通常・3枚参照・汎用・文字・ラフ・クラウドの各経路で、自由記述とnegativeを検査し、確認後の日本語追記なし | 各経路の実送信payload、LLMは模擬 |
| 確認省略ON | 翻訳成功後に生成へ進む。確認窓0回。失敗時はエラー表示・生成送信0件 | 実UI、固定の成功・失敗応答 |
| 確認省略OFF | 全文表示中は生成送信0件。はいで表示内容を1回だけ送信、いいえで編集へ戻る | 実UIと送信payload比較 |
| 編集・相談を継続できる | いいえの後もチャットで単語相談と修正ができる。最新指示を共有し、再確認した文を送る | 実UIと模擬ツール応答 |
| 承認後の競合を防げる | 入力・対象の変更や取消し後に古い承認で送らず、連打で二重生成しない | 遅延応答と実状態遷移 |
| 画像のみの応答も失わない | 画像カードを表示し、翻訳は未完了。原稿変更・後続生成0件 | 模擬API画像、実受信・表示経路 |
| 候補を明示採用できる | 画像を選んだときだけ指定先へ新規追加。元レイヤー保持、連打で1追加、Undo/Redoと保存再読込で整合 | 実編集UI、合成PNG、保存往復 |
| 候補の寿命を分離できる | 会話の折りたたみ・履歴上限では画像を保持。取り込み失敗後も候補が残り、採用資産は候補終了後も利用可能 | 実UI・資産参照の確認 |
| 翻訳の意味を維持できる | 日本語部分を意味に沿って英訳し、既存英文・描画する原文・参照役割を保持 | 選択した実モデルの応答を内容レビュー |
