# モデル設定・画像生成・キャラ照合（ビジョン）仕様

採用日: 2026-11-05
最終改訂: 2026-11-25

**状態: 2026-11-25 改訂の現行仕様。** モデル設定の分け方、2画像既定の画像生成（ローカル／クラウドAPI／外部エージェント）、部分修正用の3画像構成、オプションのキャラ照合（ビジョン）についての正本とする。ローカル画像生成の ComfyUI 登録・実行の詳細は [ComfyUIワークフロー接続仕様](COMFYUI_WORKFLOW_SPEC.md) に従う。

## 1. 環境設定の見せ方

タブは追加せず、既存の「環境設定 → モデル設定」を次の3つの区画に分ける。全用途を一括で切り替える選択は設けない。

| 区画 | 選択肢 | 担当する処理 |
|---|---|---|
| 会話 | ローカル／API | 編集画面での会話・操作支援。**プロンプト英訳機能は持たず、UIにも表示しない** |
| 画像生成 | ローカル（ComfyUI）／クラウドAPI／外部エージェント | 実際の画像生成。通常生成は2画像参照（設定画＋あたり／3Dポーズ、プロンプト流し込みなし）。3画像は部分修正時のみ使用 |
| キャラ照合（ビジョン） | チェックボックスで ON / OFF（**既定 OFF**・ON 時の既定実行先はローカル）。ON 時は ローカル（共有軽量エンコーダ／任意VLM）／クラウド Vision API を選択 | ネームから切り抜いた人物と登録キャラの照合・アングル推薦、および任意の特徴抽出 |

- 選択中の方式に必要な接続先・モデル・ワークフローの欄だけを表示する。
- 名前・顔・口調・音声は「会話」の「エージェントの設定」にまとめる。接続方式を変えてもプロフィールを保持する。
- 英訳設定（「英訳後の確認を省略して生成する」等）および英訳確認フローは廃止し、UI・設定項目から除外する。

## 2. 画像生成の実行先と方針

### 2.1 通常生成（2画像参照・プロンプト流し込みなし）

- **基本構成は2画像参照**とする：
  1. `キャラクター設定画`（登録済みの設定画から選択）
  2. `参照画像`（既定は **キャラクターあたり**。必要に応じて 3D ポーズ画像や別レイヤーへ切替可能）
- ローカル（既定 `P-H3-Image_Edit_Mac_bf16_v2`）・クラウドAPI ともに、**単画像生成ダイアログに不要なプロンプト流し込み欄は表示しない**。
- VLM による設定画からの特徴テキスト抽出をプロンプトへ自動注入する経路は使わない。

### 2.2 部分修正（3画像参照）

- 3画像構成は **部分修正（元絵 ＋ 修正マスク／赤入れ ＋ キャラクター設定画）** の用途に限定する。
- 部分修正時のみ、修正内容の短い指示を入力できる。

### 2.3 実行先ごとの挙動

| 実行先 | 対応範囲・挙動 |
|---|---|
| ローカル（ComfyUI） | 既定は `P-H3-Image_Edit_Mac_bf16_v2`（2画像参照・プロンプト不要）。参照レイヤーの既定はキャラクターあたり。ComfyUI API 経由で実行し、透過・候補採用を行う |
| クラウドAPI（Gemini Image 等） | **ページ一括生成**および**単画像生成**に対応。単画像生成では「生成」ボタンから1回生成を送信し、キュー送信完了と同時にダイアログを閉じて編集画面へ戻る。完了時にあたりレイヤーの最上段へ自動配置し、元のあたりレイヤーをレイヤー上に残したまま自動で非表示（`visible: false`）にする。応答取得後にクラウドとの HTTP 接続を閉じる（`Connection: close`） |
| 外部エージェント（Codex 等） | 作品フォルダ直下へ軽量なクラウド生成用 JSON（`<タイトル>-cloud.json`）とカットラインガイドを書き出し、外部エージェントで生成した画像を読み込む。単画像ダイアログの不要なプロンプト欄は表示しない |

## 3. キャラ照合（ビジョン）のオプション設計

キャラ照合・特徴抽出は、学習済み M1 軽量画像エンコーダ（ONNX）の配布重みが導入されるまで誤割当を防ぐため、**チェックボックスによるオプトイン（既定 OFF・ON 時の実行先既定ローカル）** とする。

- **ビジョン OFF（既定）のとき**：
  - キャラクター設定では **キャラクタービジュアル（設定画）の登録・管理のみ** を行う。
  - 外見特徴（`recognition`）の入力項目および VLM 特徴抽出ボタンは **グレーアウト（無効化）** する。
  - ローカル VLM の導入・起動は一切不要。パッケージ配布時の最小構成として動作する。
- **ビジョン ON のとき**：
  - 実行先として **ローカル（共有軽量画像エンコーダ既定／任意でローカル VLM）** または **クラウド Vision API** を選択できる。
  - ローカル照合時、学習済み M1 ONNX 重みが未配置の場合は未学習フォールバックで誤紐づけを行わず `none` として安全に棄却する（重い 8B VLM は `engine: "vlm"` 明示または特徴抽出時のみ使用）。
  - **クラウド Vision API のモデル**：画像生成用の `-image` モデルとは別の **マルチモーダル（Vision 対応）テキストモデル** を紐づける（Gemini 系では **Flash-Lite 系**（例：`gemini-2.5-flash-lite`）を既定とし、精度重視の選択肢として **Flash 系** も選択可能）。
  - API キーは画像生成用と **同一のクラウド API キーを共用** し、二重登録させない。同じ `:generateContent` エンドポイントで JSON 応答を受け取る。

## 4. 接続登録・セキュリティ・実行境界

- 認証情報（API キー）は実行側の Mac（環境変数または `~/.nyamuru/cloud_api_key`）で管理し、ブラウザーの保存領域・作品ファイル・OMNY/OMAY・JSON 出力へキーを含めない。
- API キーの登録と、各機能（画像生成／キャラ照合ビジョン）の有効化は分離する。キーを登録しただけでビジョンを自動で ON にしない。
- 一つの処理の送信先は開始時に一つへ固定し、失敗時にローカル／クラウド／別モデルへ自動で切り替えない。
- クラウドAPI利用時は、ローカル文章 LLM やローカル VLM の起動・停止・復帰を行わない。
- クラウドAPIへのリクエストは1回ごとに接続を閉じる（`Connection: close`）。

## 5. 会話で受け取った画像の任意採用

- 会話応答に画像が含まれた場合は、会話欄へ画像カードを表示し、「拡大」「編集画面に取り込む」「画像を保存」を提供する。
- 利用者が明示的に取り込みを選んだときのみ、既存レイヤー・あたり・手動ロックを保ったまま新規レイヤーとして追加する。
