# ネームの表情辞書・外見の英語読み取りと画像寸法の合同確認計画

2026-11-02。表情・外見の読み取りと保存まで実装。リサイズとの合同確認は実機試験待ち。新規取込時に、ネームの一場面の表情と設定画の安定した外見を、それぞれ最初の読み取りから英語で記録する。人物3枚参照に渡る英文は、生成前の編集欄で確認できるようにする。

## 採用した辞書と添付プロンプトの扱い

手元の正本は `Desktop/tools/資料/qwen-vl-expression-reference-2026-10-30/catalog.json`。10カテゴリ・86項目、SHA-256は `6bd93e067410380469bdbad8ef13615a9a52439b44d5e4394823f1c5d43b01b6`。指定された `revision-backups/star-eyes-v2` の revision 欄はS070修正までで、正本にはS071の瞳孔修正も記録されている。資料の編集元・見本は元の場所に置き、必要な機械可読データを版・出典とともにアプリへ同梱した。

表情部分は利用者の添付英文を基にした。読み取りプロンプトには次の方針を適用する。

- **部分一致を採用する。** ベース感情・眉・目・口・漫符の5枠とし、目と眉は独立に選ぶ。ベースはC01〜C07のうち役割が `whole_expression` の項目から最大1件。汗などの `feature` を顔全体の感情にしない。見えない・区別できない部位は未判定、漫符がなければ空配列、顔がなければ `faces: []` とする。感情が決まらなくても読めた口や汗は採用できる。
- **省略は証拠にしない。** 黒い塗りやハイライトの省略だけでS053・S054・S066を選ばない。驚いた雰囲気だけでも選ばない。S066には両目が空の円記号として描かれた積極的な根拠が要る。通常の虹彩線が残れば通常目、そこまで読めなければ未判定とする。涙と汗は起点と位置、記号目は線の角・曲率・本数を見る。
- **目全体と虹彩内の模様を分ける。** S070は虹彩内のハート、S071は丸い虹彩の中の星形の瞳孔、S072は虹彩内の複数の輝き。いずれも通常の目の輪郭を保つ。S073の三白眼、S083/S084の片目閉じも、C08の記号置換と区別する。記号目フラグはカテゴリだけでは決めない。
- **IDは出典、生成には部位の英文を使う。** `visual_description_en` は多くが顔全体の一文で、部位別の英文配列ではない。対象に見える部位だけを短い英語句として選ぶ。辞書にその部位の英文がない場合は、画像からの英語の観察と辞書由来の句を区別する。S050を口に使っても、ベースに `expressionless` を足さない。`selected_tags` を一括で生成文に連結しない。
- **設定画にない目を描かせない。** 通常目テンプレートの「二重まぶた・濃いまつ毛・精密な瞳」は外し、目の描き方はimage2に委ねる。image1が構図・ポーズ、image2が外見・ペンタッチ、image3が表情を担当する。英文例は “Use the expression from <image3>: slightly lowered inner brows, half-lidded eyes, and a short, straight, closed mouth.” この例のIDや形は他の顔の既定値にしない。画像の役割を示すラベルは実装では既存の生成テンプレートだけが付ける。

## 既存の読み取り経路と出力

- **人物切り抜きの表情**: [演技読み取り](../scripts/local_figure_performance_worker.py)の同じ画像・同じ推論で、姿勢・描写範囲・顔を観察する。[人物照合](../scripts/local_character_match_worker.py)からもこれを使う。[同梱辞書](../scripts/expression_catalog.json)は正本86件のID・順序・役割と英語の手掛かりを使い、見本画像、資料のパス、日本語訳、未選択のタグを生成側に送らない。WD Taggerは補助候補のみ。
- **部位と演技文**: 顔ごとに正規化した切り抜き内のbbox（xyxy、不明ならnull）、確信度、ベース感情・眉・目・口・漫符を記録する。部位のIDと観察句を分け、辞書の英文を直接使ったか、画像からの英語観察かを記録する。生成用の表情文は検証済みの部位から組み立てる。人物の所属が不明な複数顔は要確認とし、他の顔の表情を演技文に入れない。顔なしでは空配列とし、読めた姿勢や人物照合を残す。
- **外見**: [設定画読み取り](../scripts/local_character_reference_worker.py)の顔・体・注記の各処理が、恒常的な特徴だけを短い英語句として返す。通常画面で設定画を1枚選んだときも注記にOCR原文が届き、文字の拡大と設定画を照合する。複数枚の比較では顔と体を各々比較し、OCRは送らない。名前・別名・一時的な表情やポーズは外見の根拠にしない。人物照合に送る候補はIDと採用済みの観察語だけで、台帳に手入力した語は原文を保つ。
- **取込と保存**: 同じ原画領域から生じた各配置の `analogImport.expressionReading` に辞書版、元辞書SHA-256、顔・部位の根拠を保存する。ここはローカルの作品記録で、OMNYからは除外する。演技文は既存の編集可能な `Figure.action` に入る。3枚参照には現行の演技欄と台帳を使い、解析記録や辞書を足さない。画像の役割は生成テンプレートにあるので、読み取り文には `<image2>` や `<image3>` を足さない。

応答例（顔1件の`parts_mapping`部分、固定入力での仕様例。実際のQwen-VL出力ではない）:

```json
{
  "base_emotion": null,
  "brows": null,
  "eyes": {"id":"S010","evidence_en":"half-lidded eyes","source":"catalog","is_symbolic_eye":false},
  "mouth": {"id":"S050","evidence_en":"a short straight closed mouth","source":"catalog"},
  "extras": []
}
```

この例では半目と閉じた直線口が演技欄に入り、顔全体に `annoyed` や `expressionless` を追加しない。元画像のリサイズ規則、実機の生成結果、全体テストは今回の局所確認に含めない。
